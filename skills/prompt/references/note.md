# Note

The note tells the user what only they can answer before the prompt runs. It opens with `Before it runs:`, then 1-3 numbered one-line items, most material first. With no item admitted, write no note.

- For a choice, give 2-3 lettered options in fixed order, best marked: `1. Features: a) keep all (best) b) may change`. For a free value, say what to give.
- Then add the line `Reply ok to run as is, or answers like 1a or 2: <value>.`. For an in-session prompt, `Ok to run it?` follows.
- Admit an item only when the user alone can supply it and it could change the work materially. Each kind below that fires gets an item:
  - Paid job: a money cap.
  - Change of unclear size: how big (improve, remove, rewrite; features stay or not).
  - Named skill whose description rules out the task: keep it in the prompt and quote the clause.
  - Two readings leading to materially different work: name both.
  - Named path, file, symbol or skill that step 2 did not find: check the name, but not for one the prompt creates.
- A suggested item never puts a value in the block, since the reply supplies it.
- These are not items: what `## Add` puts in the block, a report of the rewrite, wording polish, anything the block answers, and one shown earlier.
