# Plugging holes

Every rationalization the model produced under the skill becomes one addition to the skill. The enemy is the vague counter such as "do not cut corners", which the next run reads past. The overcorrection is a skill that grows one paragraph per excuse until the rule that mattered is buried.

## The four-part plug

For each new rationalization, in this order, stopping when the next rerun passes:

1. Add the explicit negation to the rule itself, naming the workaround: "keep it as a reference" and "adapt it" are also deletions the rule forbids.
2. Add a row to the red flags table with the excuse verbatim and the reality in one clause.
3. Add the excuse's tell to the description as a symptom, so the skill fires at the moment the excuse forms.
4. State early that breaking the letter breaks the spirit, once, when the model argues the rule does not apply to its case.

## Re-verify

The skill holds when the rerun chooses right under the strongest combined pressure, cites the section that stopped it, and names the temptation it felt.
It does not hold when the rerun invents a new rationalization, argues the skill is wrong for this case, proposes a hybrid, or asks permission while arguing for the violation.

## Meta-test

Ask the model that failed how the skill should have been written, and route its answer:

| Answer | Fix |
|---|---|
| "The skill was clear; I chose to ignore it." | Add the spirit-over-letter line and a bright line; the wording was not the problem. |
| "It should have said X." | Add X in those words. |
| "I did not see section Y." | Move Y earlier or into the opening; reorganize, do not add. |

## Mistakes

- Skipping the baseline, so the pass is unexplained.
- One pressure only, so the second pressure in production finds the hole.
- Paraphrasing the excuse, so the table row misses the wording the model actually uses.
- Stopping after the first pass instead of rerunning every case after the plug.

## Judgment

- A plug that names the workaround outranks a plug that restates the rule.
- Reorganizing outranks adding when the model missed a section that existed.
- One skill through the whole loop outranks two skills half done; the next skill starts when this one passes every case.
