# Question shape

Ask the costly questions one per message. The enemy is developer words or stacked choices; the overcorrection is context that buries the choice.

## Each message

No code name anywhere, assumptions included: no path, field, setting or technical term, only what it means for the user.

- First line `Question <n>`, counting up by one each question turn.
- One context line only if needed, then the question in everyday words.
- Two or three one-line options `a.` `b.` `c.`, each only what the user gets.
- Recommended first, with the output style's marker, else `(recommended)`.
- Under them, one unlabelled sentence under 20 words on why it wins.
- Last, one reply hint line; no recap.
- Ask first the question that could remove others.
- Only the final question adds `Assuming:` above the hint: one line per user-visible default neither request nor code fixes.

```text
Question 2

Who may download the tide alerts?
a. Harbour masters, for their own harbour. (recommended)
b. Everyone who can see the alerts.
Bulk harbour plans should not reach outsiders.

Assuming:
- The export uses the alert list's date format.
- The download button sits beside the refresh button.

Reply a, b, your own words, or ok to take this and every assumption.
```

## Replies

- A letter or own words answers the current question; the next comes alone.
- `ok` or `go` takes this and every remaining recommendation and assumption; an unanswered question takes its recommendation.
- The final answer confirms: the brief follows, no confirmation round.
- A reply opening a new costly point adds one question.
- "I don't know" gets two everyday sentences on the difference, with one example, then the question again; a second takes the recommendation, credited to exo.

## Judgment

- Everyday words outrank precision.
