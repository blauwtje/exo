# Plugging holes

## Closing one excuse

Apply these in order, rerunning after each, and stop at the first rerun that passes:

1. **Name the workaround in the rule.** Extend the rule so it forbids by name the route the model took, for example: "renaming the old function and keeping it" is also keeping it.
2. **Quote the excuse in the red flags.** Add a row holding the model's exact words and, in one clause, what is true instead.
3. **Put its tell in the description.** Add the thought that came before the excuse as a symptom, so the skill loads at the moment that thought appears.
4. **Say letter and spirit are one.** Once, early in the body, state that getting around the wording of a rule breaks the rule, for the model that argues its case is the exception.

## When it holds

It holds when the rerun under the heaviest stacked pressure picks the right action, points to the section that stopped it, and names what tempted it.
It still leaks when the rerun finds a fresh excuse, argues that the skill does not fit this case, offers a compromise, or asks permission while making the case for breaking the rule.

## Asking the model

Ask the run that failed how the skill should have been worded, and act on the kind of answer:

- It says the skill was clear and it went its own way: add the letter-and-spirit line and a bright line, because the wording was never the gap.
- It proposes a specific sentence: add that sentence in its words.
- It says it never noticed a section: move that section earlier or into the opening, and add nothing.

## Judgment

- A change that names the workaround outranks one that repeats the rule.
