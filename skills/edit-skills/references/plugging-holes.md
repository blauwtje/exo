# Plugging holes

## Closing one excuse

Apply in order, rerun after each, stop at the first rerun that passes:

1. **Name the workaround in the rule.** Extend the rule to forbid by name the route the model took: "renaming the old function and keeping it" is also keeping it.
2. **Quote the excuse in the red flags.** Add a row: the model's exact words, and in one clause what is true instead.
3. **Put its tell in the description.** Add the thought that preceded the excuse as a symptom, so the skill loads when that thought appears.
4. **Say letter and spirit are one.** Once, early in the body: getting around a rule's wording breaks the rule. Targets the model that argues its case is the exception.

## When it holds

- Holds → rerun under heaviest stacked pressure picks the right action, points to the section that stopped it, names what tempted it.
- Still leaks → rerun finds a fresh excuse, argues the skill does not fit, offers a compromise, or asks permission while arguing for breaking the rule.

## Asking the model

Ask the failed run how the skill should have been worded; act on the answer kind:

- Skill was clear, it went its own way → add the letter-and-spirit line and a bright line; wording was never the gap.
- Proposes a specific sentence → add it in its words.
- Never noticed a section → move that section earlier or into the opening; add nothing.
