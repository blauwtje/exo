# Source quality rubric

Judge each page before you write it down as evidence. The numbers (age, votes, stars, views) are scored by a script; this rubric covers what a number cannot show.

## Drop the page

- An SEO farm: a thin page of generic advice, affiliate links, a "top 10" list with no first-hand detail, or text copied from another page.
- Vendor marketing used as proof of the vendor's own claim: a launch post, a pricing page or a case study with no method or number you can check.
- Stale for the question: it names an older model, version or API than the one asked about, or its date is before a change the question depends on. Keep it only when the question is about history, and say so in the title field.
- A page that does not hold the text you would quote: a login wall, a cookie page, a search results page, a tag or category page.

## Mark the page primary

Set `primary` to true for the original: the official docs, the paper, the repository or issue itself, the standard, the first-party data or the author's own post. Set it to false for a summary, a roundup, a forum answer that cites another page or a news article about the original. When both exist, read and quote the original.

## Weigh the rest

- A claim two independent sources make counts for more than one source repeated by five pages that copy each other.
- A named author with a track record, a maintainer or an accepted answer beats an anonymous post with the same text.
- A page that gives its method, a number with its unit and a date beats one that gives only a verdict.
- When sources disagree, keep both and say what differs: version, date, setup or definition.
