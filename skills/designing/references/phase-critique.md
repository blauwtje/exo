# Phase 4: Render budget

Render at three checkpoints and nowhere between them. The enemy is a render between repairs that spends the budget confirming edits already watched. The overcorrection is a design reported complete without its baseline, post-build and final pairs.

## The mechanics

A full or bounded redesign renders at three checkpoints, each at 390px and 1440px: baseline before the first edit, post-build before the critique fixes, and final after them, captured with `scripts/capture.mjs --full-page --out "$RUN/renders"`. On rungs 3 and 7 of the skill's `## Route` the baseline pair follows the selection, because nothing renders before the offer is answered. A surface that did not render before the run takes no baseline pair, because nothing exists for the result to stay interchangeable with. The baseline and final pairs are this session's; the post-build pair belongs to one dispatch of the `exo:design-critic` agent, whose file pins `opus`, `high` effort and its turn limit. It receives `RUN`, `URL`, and `SKILL` as the absolute directory this skill loaded from, captures, runs `scripts/check-ui.mjs` and `scripts/inspect-render.mjs`, opens the renders in its own context, and writes faults.md in `$RUN`. Those six, or four without a baseline pair, are the render budget for Phases 4 and 5: read faults.md with `head -60`, and when the critic returned without writing it, resume that same critic once to write the file from what it already read, never a fresh dispatch that renders again; repair every fault, sending all of one surface's faults to its builder delegate in one call and repairing a one-line fault or an in-session surface directly, because each builder call re-reads the contract and the foundation, then prove the repairs with this session's own `scripts/capture.mjs` final pair and one `scripts/check-ui.mjs` run at 390px and 1440px. One reviewer round is the cap, because a second reviewer context re-reads the whole surface to confirm edits this session watched land; a fault the final pair still shows is reported, not chased. No render between repairs, no probe page against the engine, no repair for an engine quirk the source does not show; when a capture contradicts a rule the source follows, report it and move on. No MCP browser tool inside this skill — no `browser_screenshot`, `browser_evaluate`, or snapshot against the surface: the render path is `scripts/capture.mjs` and the reviewer. After the reviewer's report this session spends at most 12 tool calls on Phases 4 and 5 together; past that, report what remains open.

## Judgment

- One reviewer round is the cap: a fault the final pair still shows is reported, not chased.
- The source outranks an engine quirk a capture shows: report the contradiction and move on.
