# Build-speed idea ledger

This file records every build-speed idea that did not land, or landed without a measured gain, so it is known and not tried again.
An idea is retried only when the circumstances in its "Retry when:" line change and it now looks promising.
A new non-landed idea gets a line here in the change that drops or defers it.
New entry → add its line to the index below and its full entry in a section after it, in the same change.

## Not landed, or no measured gain

- **Reuse the build's passing Proof run at landing** (candidate 3: `land-task.mjs --check` records the pass so land-task skips its rerun). Status: deferred. It touches the anti-fabrication boundary (the pass must be recorded by the script, never by the model's claim), and its gain shows only when a Proof is slow; the flow fixture's proofs run under 1 s. Evidence: unmeasured. Retry when: a real run shows a slow Proof rerun at landing (the 2026-10-10 baseline gate runs took 69-120 s). Round 2 note: a script-written build report (`--check --compose`) is its output-side superset, listed below.
- **Compact build tasks at medium effort as speed-pass Task 6** (`perf(agents): run compact build tasks at medium effort`, reverted in `f21c4311`). Status: rejected. The branch arm carrying it had a 315.2 s median wall against 189.9 s for main, and the repaired arm without it was still 28% above main; n=3, so the gap is within noise. Evidence: [2026-10-02-speed.md](results/2026-10-02-speed.md). Retry when: a larger run-to-run sample or a pressure cell shows the lower effort keeps the pass rate and cuts wall time (`build-task` at `medium` later landed on pass rate and cost alone, see the pointers below).
- **Review the fix diff on the standard tier** (`700a162b`, reverted in `12085983`). Status: rejected. A replay of 10 past branch reviews x 4 repeats found opus hit 37.5% of known review findings and sonnet 6.7%. Evidence: unmeasured in a committed results file (the replay figures are in the revert commit message). Retry when: a cheaper tier matches opus on the replay set.
- **Let a dependent task refill a parallel slot.** Status: rejected. It saves about 0.3 min and changes the meaning of `Parallel:`. Evidence: unmeasured. Retry when: a run shows an idle slot waiting on a dependent task for longer than the landing it saves.
- **One gate per wave.** Status: rejected. It hides which task broke the gate. Evidence: unmeasured. Retry when: the gate can name the breaking task from one run.
- **More than 4 parallel slots.** Status: rejected. A wave of 4 halved build time (302 s to 153 s) but later stages erased the gain, and parallel gates contend for CPU. Evidence: [2026-09-29-small-waves.md](results/2026-09-29-small-waves.md). Retry when: a plan class keeps the later stages short enough that build is the bottleneck.
- **Event-driven wait instead of the 5 s `wait-report` poll.** Status: rejected. The mean latency is 2.5 s per slot, and a hook would add overhead to every session. Evidence: unmeasured. Retry when: the poll shows up as a measured share of a build's wall time.
- **Affected-only test selection in the inner loop.** Status: rejected. The Proof is already one named test file, and land gates are cached or skipped when slow. Evidence: unmeasured. Retry when: a repo's Proof is a whole suite and the cache misses on every task.
- **Lower lead effort or a condensed lead context.** Status: rejected. The lead-context review found no change without a quality cost, and one paper reports aggressive compression raised billed cost by 6.8%. Evidence: unmeasured. Retry when: a measured lead-context cut keeps the hidden-test pass rate and the billed cost does not rise.
- **Cache warm-up stagger before fan-out.** Status: rejected. It is harness-level, `run-unit` already uses a 1-hour cache TTL, and the gain is cost, not wall time. Evidence: unmeasured. Retry when: the harness exposes a measured wall-time effect of cache warm-up.
- **Reviewer fan-out or precision filtering.** Status: rejected for the build field. Review lives in verify. Evidence: unmeasured. Retry when: the work is scoped to verify speed.
- **Speculative next-action execution.** Status: rejected. One paper, outside coding, and cost goes up. Evidence: unmeasured. Retry when: a coding-task result shows a wall-time gain at flat cost.
- **Haiku for `run-unit`.** Status: rejected. Routing risk is too high for an unmeasured gain; effort was tested first. Evidence: unmeasured. Retry when: `run-unit` at `low` effort holds its routing pressure cases and a cheaper tier still looks needed.
- **`land-slot`: land one slot in one script call** (`a0f90e0b`). Status: landed-but-no-gain. Run-unit calls fell 15% (15.3 to 13.0) but total wall, cost and tokens show no effect n=3 can support. Evidence: [2026-10-19-build-speed-rerun.md](results/2026-10-19-build-speed-rerun.md). Retry when: not retried; revisit if a larger-n run on a wave-heavy plan shows no wall gain, to decide on removal.
- **Skip `wait-report` after a foreground `Next:` build** (`a0f90e0b`). Status: landed-but-no-gain. Run-unit never called `wait-report` after a foreground build in either arm, so the rule changed no behavior. Evidence: [2026-10-19-build-speed-rerun.md](results/2026-10-19-build-speed-rerun.md). Retry when: a run shows `run-unit` waiting on a foreground build.
- **`run-unit` at `low` effort on the balanced profile** (`a0f90e0b`). Status: landed-but-no-gain. It applied in 2 of 3 candidate runs, run-unit wall fell 25-34% with overlapping ranges, and total wall, cost and tokens show no supported effect. Evidence: [2026-10-19-build-speed-rerun.md](results/2026-10-19-build-speed-rerun.md). Retry when: a rerun with the effort applied in every run, and the review stages held equal across arms, shows a total effect.
- **Scripted acceptance of the fix diff replaces the second `review-branch`** (`run-probes.mjs --scope`: the fix touches only files named by `fix` findings, drops no test or assertion, adds no skip marker, stays under a size cap). Status: untried. It saves about 13 s per run and one review dispatch, but the probe proves the finding fixed, not that the fix adds no new defect. Evidence: unmeasured (transcript estimate). Retry when: a run with a `fix` finding shows the second review adding no finding on the fix diff across several runs.
- **`verify.mjs` runs the reviewer's mechanical rules** (the `Red:` grep, test-first per task, deleted tests, removed assertions and skip markers become `defect` lines merged by `merge-reviews.mjs`). Status: untried. It saves 10-20 s per run of reviewer round trips and cannot be skipped by a model, but a regex can miss a test runner it does not know. Evidence: unmeasured (transcript estimate). Retry when: review-branch tool calls on the `Red:` and skip-marker checks show as a measured share of verify wall time.
- **A new, test-first module needs no branch review** (`pick-reviewer.mjs` returns `none` when a task only adds files, each with an added test and a non-`none` `Red:` line). Status: untried. It could remove the whole review, fix and re-review chain (59-100 s on flow-unit), but the review standard (swallowed failures, duplicate truth, dead code) is checked nowhere else and hidden tests cannot see that risk. Evidence: unmeasured (transcript estimate). Retry when: code-rules and static checks cover the review standard for new modules, shown on a seeded-defect fixture.
- **Speculative pathfinder: fan out the wave with Task 1 and hold landings until it lands** (`land-slot.mjs` refuses `HOLD` while the pathfinder is unlanded). Status: untried. It saves about 25-30 s on runs with a ready wave at start, but a failing or drifting Task 1 wastes up to three builds (about 11-15k tokens each). Evidence: unmeasured (transcript estimate). Retry when: the script-owned fan-out has landed and a run shows the Task 1 alone phase on the critical path.
- **Lead stages verify while `run-unit` builds** (run-unit runs in the background and writes its return to a file; the lead reads the review rules and picks the reviewer, then blocks on one `wait-report`). Status: untried. It saves 12-20 s per run, but a BLOCKED return must still route before verify and the return file is new state. Evidence: unmeasured (transcript estimate). Retry when: a run shows the lead's verify prep after the build as a measured gap of over 15 s.
- **Rolling review: review starts while the last slot is still building** (`wait-landed.mjs`, a full-diff pass at the end). Status: untried. It saves 5-30 s depending on how uneven the tasks are, but a split review can miss cross-task defects and it needs about 120 lines in 6 files. Evidence: unmeasured (transcript estimate). Retry when: the other verify-phase cuts leave the review as the critical path and tasks differ widely in build time.
- **The dispatch carries the read set** (`next-task.mjs` prints a filled `implementer-prompt.md` block with the brief, `run-rules.md` and `lean.md` inlined, so `build-task` and `run-unit` skip their reads). Status: untried. It saves 10-20 s per run (3 turns per build-task, 2 per run-unit dispatch round), but the prompt grows and the brief is no longer read from its file. Evidence: unmeasured (transcript estimate). Retry when: a run shows the brief and rules reads as a measured share of build-task wall time.
- **One review bundle file read with Read** (`verify.mjs --reviews-only` writes `.exo/review-input.md` with the plan goal, non-goals, context, diff and standard paths, under the output spill size). Status: untried. It saves 4-8 s per review by avoiding the `<persisted-output>` detour and the failing plan `cat`, but the bundle must stay current with the diff. Evidence: unmeasured (transcript estimate). Retry when: reviews keep spilling tool output in a larger sample.
- **Verdict-first review output with a finding cap and a `--diff-only` scope for the fix-diff review** (`review-branch.md` writes `VERDICT`, then at most N finding lines, no "checked, fine" prose). Status: untried. It saves 12-25 s per run, but less thinking aloud may miss defects, the highest quality risk of the verify ideas. Evidence: unmeasured (transcript estimate). Retry when: a seeded-defect fixture shows the catch rate unchanged with the shorter output.
- **Invariant-edge Red: a `Data:` quantifier ("exactly", "at most", "never") needs a Red test at inputs 0, 1 and below any constant** (`test-design.md` rule, optionally a `land-task.mjs checkTask` guard). Status: untried. It removes the review, fix, probe and re-review loop when it fires (about 25 s per run on average, 2 of 6 runs), but it can over-test trivial tasks. Evidence: unmeasured (transcript estimate). Retry when: a run again shows a reviewer finding a defect at an edge input that the plan's `Data:` states.
- **Script-written build report: `land-task.mjs --check --compose`** (the model states landed clause, Red and test-first; the script runs Proof, writes the `.diff`, `.log` and report block). Status: untried. It saves 20-35 s over four tasks and removes report-format retries, but it overlaps with candidate 3 above and must land as its output-side superset or after it. Evidence: unmeasured (transcript estimate). Retry when: candidate 3 has landed, or build-task report turns show as a measured share of its wall time.
- **Short verbs: a `bin/exo-step` command (`next`, `land 3`, `wait 2,3`, `check 3`) reading plan and root from `.exo/run.json`.** Status: untried. It saves 30-35 s per run in about 2.2k fewer output tokens, but plan and root can resolve wrongly in a slot worktree and it touches prompt lines in 4-5 files. Evidence: unmeasured (transcript estimate). Retry when: the harness puts plugin `bin/` on PATH, or lead and run-unit command lines show as a measured share of output tokens.
- **Cache TTL of 1 hour on `build-task`, `review-branch` and `fix-review`** (`subagentPromptCacheTtl` or per-agent `experimental: { cacheTtl: 1h }`, now set only on `run-unit`). Status: untried. It saves cost on cache re-reads between parallel siblings and across a long run, with little wall effect, and the setting name is unverified. Evidence: unmeasured (transcript estimate). Retry when: a run shows cache writes on these agents after a gap of over 5 minutes.
- **`omitClaudeMd: true` on `build-task` and `review-branch`** (already set on `fix-review`, `locate-code`, `fetch-docs` and the UI agents). Status: untried. It trims input tokens per call, but these two agents may need the project rules in `CLAUDE.md`, and the field name came from a truncated fetch. Evidence: unmeasured (transcript estimate). Round 3 note: the SDK [AgentDefinition table](https://code.claude.com/docs/en/agent-sdk/subagents) now confirms `omitClaudeMd` (TypeScript SDK 0.3.271 or later; Python lacks it), so only the pressure cell is missing. Retry when: the field is confirmed in the sub-agents docs and a pressure cell shows the two agents keep their pass rate without `CLAUDE.md`.
- **`--bare` for headless `claude -p` runs** (skips hooks, plugins, MCP and `CLAUDE.md` discovery). Status: untried. It cuts start-up time per headless call, but it needs `ANTHROPIC_API_KEY` and `--plugin-dir`, and exo's use of headless calls is unchecked. Evidence: unmeasured (transcript estimate). Retry when: a headless `exo run` start-up shows as a measured share of wall time.
- **Fix the usage and error text of exo's scripts from run-log error counts** (mine run logs for retries and invalid-argument errors on `next-task`, `land-task`, `land-slot`, `wait-report` and `verify`; rewrite the text they hit, or add a check that fails on a new error without a hint; one-time, not a new agent stage). Status: untried. It removes retry turns (the `--compose` entry names report-format retries) at lower cost with quality unchanged, but the 40% task-time cut that motivates it is specific to Anthropic's research tools. Evidence: unmeasured, confidence medium (two sources agree): [multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system), [writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents). Retry when: run logs show repeated retries or invalid-argument errors on one script.
- **Script stdout contract: a few lines by default, one `ERROR <reason>` line per failure, detail to a `.exo/*.log`, `--verbose` for the rest** (stays under the 25k-token tool-output cap so nothing spills to `<persisted-output>`; `npm run check` could lint it). Status: untried. It saves a little wall time (fewer spill detours, shorter reads) and input tokens, but it is a repo-wide rule where the "one review bundle" entry covers one file, and no wall figure exists. Evidence: unmeasured, confidence medium-low (principle agreed, no wall figure): [building a C compiler](https://www.anthropic.com/engineering/building-c-compiler), [writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents) (concise format 72 vs 206 tokens). Retry when: tool outputs of exo scripts keep spilling or long outputs show as a measured share of input tokens.
- **Fork dispatch for wave siblings** (after the lead reads the brief and rules once, spawn wave `build-task`s as forks that inherit the lead's cached conversation instead of fresh agents that re-read them). Status: untried. It could skip 2-3 read turns per task and a cold cache write, but cost is uncertain (the fork carries the lead's context), and it breaks the clean-room `build-task` design with lead bias. Nearest entry: "The dispatch carries the read set", which inlines text; a fork shares the cache instead. No Anthropic-engineer talk transcript was found; the only talk summary read is third-party ([dev.to](https://dev.to/kazuya_dev/aws-reinvent-2025-what-anthropic-learned-building-ai-agents-in-2025-aim277-16lc)) and it says sub-agents "didn't parallelize well in practice", so the claim below rests on docs and blog posts, not a talk. Nearest entry: script-owned fan-out (`next-task --slots`, branch `speed/fan-out`), which stays inside the lead's turns. No Anthropic-engineer talk transcript was found; the only talk summary read is third-party ([dev.to](https://dev.to/kazuya_dev/aws-reinvent-2025-what-anthropic-learned-building-ai-agents-in-2025-aim277-16lc)) and it says sub-agents "didn't parallelize well in practice", so the claim below rests on docs and blog posts, not a talk. Evidence: unmeasured, confidence low (one source): [SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents). Retry when: a run shows a task looping past a turn count that a cap would have cut, and the frontmatter field is confirmed.

Status: untried. It could save the re-read per repair at lower cost, with the context growing, but `run-unit` already has `SendMessage` and exo may already do this; check current behavior first. Retry when: Claude Code exposes the thinking mode per agent and `run-unit` holds its routing pressure cases with it.
