# find-open-points ceiling stays at max

Tested on 2026-11-07 as a paid A/B with `benchmarks/agent-tier.mjs --agent find-open-points --tier full`, 8 brief fixtures (`benchmarks/agent-tier/find-open-points/`, b1 to b8), one run per cell. The max arm reuses the first A/B (`benchmarks/results/2026-11-07-fop-ab.md`) for b1 to b3 and b5 to b8, and reruns b4 with a raised wall cap. The xhigh arm is new. Scripts, transcripts and grades are local and untracked under `.exo/fop-xhigh/` in the worktree.

Idea: the `open-points` kind ceiling in `lib/model-kinds.json` drops from `max` to `xhigh`, so a max-effort session runs the open-point agent at xhigh.

Verdict: FAIL on recall. The ceiling stays `max`.
Number: with all 8 briefs measured, recall is xhigh 40/54 (74.1%) and max 47/54 (87.0%). That is 12.9 points apart, outside the 5-point guard. The bucket saving would be 45.1%.

## max b4 rerun

- The first max b4 run hit the harness's 240 s session cap (`EXO_LOCATE_SESSION_MS`, default 240000, `benchmarks/locate-recall.mjs:21`) and scored 0. That cap is a harness limit. Real use has no such limit.
- Rerun: `EXO_LOCATE_SESSION_MS=900000 node benchmarks/agent-tier.mjs --agent find-open-points --tier full --candidate sonnet:max --concurrency 1 --max-usd 1.5`. It ran from a copy of `main` with the full fixtures cut to b4 in the copy only. No code change was needed and the default stays 240 s.
- Result: completed with score 1, 13 turns, 463 s, $0.784.
- At 463 s, b4 needs about twice the old cap. Any max A/B on this agent needs a cap of at least 600 s.

## Grading

- References: `.exo/fop-xhigh/refs.json`, 54 points over 8 briefs, sha256 `4bb68b8b7122a3164cfc5e2c36992372bcac6ed9387e4baf6facc45b995d77f8`, checked before each grading. It is the same file as in the first A/B.
- b1 to b3 and b5 to b8: graded blind for both arms in one shuffle of 15 runs (seed 20261187). Grades went to `.exo/fop-xhigh/blind/grades.json` before `key.json` was opened.
- b4: graded blind for both arms in a new shuffle of 6 runs (seed 20261107, `.exo/fop-xhigh/b4/blind/make.mjs`): both b4 runs, with the b2 and b7 runs of each arm as decoys. Grades went to `.exo/fop-xhigh/b4/blind/grades.json` before `key.json` was opened. The xhigh b4 regrade gave 5/7, the same as its first grading.
- A point counts as matched when the run raises the same open question, as an assumption, a user point or a `Cannot follow` line.

## Cost

- Mean per session: xhigh $0.0628 (8 sessions, $0.5026), max $0.4200 (8 sessions, $3.3598, including b4 at $0.7843).
- Bucket saving = (1 - 0.0628 / 0.4200) x 53.0% = 45.1%. Here 53.0% is the max runs' share of the $20.76 real-use bucket, the same figure as in the first A/B.

## Spend

$0.50 for the xhigh arm and $0.78 for the max b4 rerun. The other 7 max cells cost $2.58 in the first A/B and were not rerun.

## Rule (pre-registered)

Set the ceiling to xhigh only when recall_xhigh >= recall_max - 5 points AND bucket saving >= 3%. Otherwise keep max.

Outcome: 74.1 < 87.0 - 5 = 82.0, so the recall condition fails, while 45.1% >= 3% passes. `open-points` in `lib/model-kinds.json` keeps `"ceiling": "max"`, and the pin in `tests/agent-effort.test.mjs` stays at max.

## Alternatives

- Ceiling at xhigh: about 6.7x cheaper per session and much faster, but 12.9 points lower recall. A missed open point costs a wrong build, which is worth more than the $0.36 saved per session.
- Ceiling at high: rejected in the first A/B (64.8% recall).
- Keep max (chosen): it has the best recall on every brief. Its cost is $0.42 and 200 to 463 s per session.

## Caveats

- The earlier PASS on 7 briefs came only from the 240 s cap scoring max b4 as 0. With b4 measured, the gap is about the same as the b4-excluded reading (74.5% vs 87.2%).
- There is one run per cell. Per-fixture differences of one or two points are noise at this n, but xhigh is never ahead.
- One grader did all the grading. The b4 decoys are runs that grader had already graded, so the decoys hide the arm but not the fact that a run was seen before.
