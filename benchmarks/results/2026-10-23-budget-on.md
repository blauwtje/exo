# Budget `on` against `balanced`, flow-unit, n=15

Gate: `on` mean cost per run <= `balanced`, and `on` hidden-test passes >= `balanced`. Verdict: **gate does not hold** (cost). Passes tie at 15/15.

## Method

- Arm balanced: exo main `3ecc0ed9` (`/Users/thomash/Documents/Code/personal/plugins/exo`). Arm on: branch `budget-routing` at `9628b216` (`.../plugins/exo-budget-routing`). The user's global setting is `pluginConfigs."exo@blauwtje".options.budget = "balanced"` in `~/.claude/settings.json`; cells inherit HOME, so it reaches both. Settings resolve to `balanced` on main and to `on` on the branch (`settingValue('budget')` in each checkout).
- Commands (one per arm, run in sequence, concurrency 5, 15 cells each, claude-sonnet-5-5 effort high, Claude Code 2.1.309):
  - `node benchmarks/improve-speed.mjs /Users/thomash/Documents/Code/personal/plugins/exo --repeat 15 --concurrency 5`
  - `node benchmarks/improve-speed.mjs /Users/thomash/Documents/Code/personal/plugins/exo-budget-routing --repeat 15 --concurrency 5`
  (runs `sweep.mjs --set flow --cells flow-unit --confirm` from the given checkout, which loads that checkout as `--plugin-dir`). `baseline-pool.mjs lookup --commit 3ecc0ed9 --cell flow-unit ... --metric cost` returned `miss`, so both arms ran. A first balanced attempt was killed by a tool timeout after a few cells and rerun from scratch; its partial cost is not counted below.
- Effective budget, from the subagent transcripts of all 15 cells per arm: `build-task` ran on claude-sonnet-5-5 at effort medium in 60/60 (balanced) and 62/62 (on) dispatches; `run-unit` sonnet low; `review-branch` and `fix-review` effort high. No `build-task` ran on opus in either arm, so no retry step-up fired in the `on` arm: the retry path is not exercised by this task. The two kind tables differ only in `doc-task`, `research` and `lookup`, which flow-unit does not dispatch.
- Stats: Mann-Whitney two-sided (Monte Carlo permutation, 200k) and bootstrap 95% CI of the mean difference (10k resamples), unpaired: the 15 cells are repeats of one task, so `measured-goal.md` paired readouts, sign test and `mde.mjs` (tbench, several tasks) do not apply.

## Result

| metric | balanced | on | on - balanced |
|---|---|---|---|
| hidden tests passed | 15/15 | 15/15 | 0 |
| cost $ mean (sd) | 0.610 (0.094) | 0.712 (0.139) | +0.102, p=0.008, CI [+0.020, +0.186] |
| cost $ median | 0.584 | 0.651 | |
| wall s mean | 129.8 | 172.2 | +42.4, p=0.002, CI [+7.0, +75.7] |
| wall s median | 115.1 | 146.7 | |
| runs with fix-review | 1 of 15 | 4 of 15 | |
| total cost $ | 9.15 | 10.69 | |

All 30 cells exit 0, no time-outs. `on` costs 17% more and takes 33% longer per run. The difference follows the review repair loop: 4 of 15 `on` runs dispatched `fix-review` against 1 of 15 balanced (round 8 saw 2 of 15 on main), and `review-branch` ran 19 times against 16. The routing table is identical for the kinds flow-unit ran, so this is most likely run-to-run variance in whether the reviewer raises a finding, not the router. The test cannot tell the two apart at n=15 (a cell with a repair loop costs about $0.93 against $0.58), so rerun with a fresh balanced arm before reading the gap as a router effect.

## Verdict

Gate: cost fails (0.712 > 0.610), passes tie. Ledger verdict `rej`. No code changed.
