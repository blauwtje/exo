# Code-size rival benchmark: template tasks

Measured lines added, weighted tokens and cost for exo and for a rival arm, `ponytail`, against a session without a plugin. Four tasks on the `full-stack-fastapi-template@cd83fc1` fixture: two backend tasks (`tmpl-be-recent`, `tmpl-be-rename`) and two frontend tasks (`tmpl-fe-copy`, `tmpl-fe-stepper`). Arms `baseline`, `exo` and `ponytail`, Sonnet 5 (`claude-sonnet-5`) at the CLI's default effort, 3 runs per task and arm, concurrency 3, 36 cells. The run started from a worktree at `e5d8d8c2`, whose plugin files are identical to `main` at `c2896af9`; Claude Code 2.1.291. No cell timed out, and all 36 cells were correct.

```bash
node benchmarks/run.mjs --tasks tmpl-be-recent,tmpl-be-rename,tmpl-fe-copy,tmpl-fe-stepper --arms baseline,exo,ponytail --model sonnet --runs 3 --concurrency 3 --out benchmarks/runs/2026-10-06-rivals
```

`Tokens` is weighted input plus output from each cell's `usage.json`, weighted as `score.mjs` weights them, the same definition as in `2026-10-06-value.md`. `Cost` is `total_cost_usd`. `Lines` is the lines added, `loc.added` in `checks.json`. Each arm cell is mean ± sample standard deviation over 3 runs. A per-task difference counts only when it is larger than 2 standard errors, √(sd_arm²/3 + sd_baseline²/3) × 2; otherwise it is noise. The pooled difference is the mean of the 4 per-task differences against the baseline, with SE = √(Σ over tasks of sd_arm²/3 + sd_baseline²/3) / 4, and the same 2 SE threshold.

## Decision

This run was step 2 of the experiment. The rule set before the run was: if ponytail beats the baseline on tokens or lines, inline a short version of exo's own ladder into exo's SessionStart text and inject the same text at SubagentStart, offsetting every added byte so that `INJECTED_CONTEXT_LOCK` (2069 bytes) does not rise; if it does not fit, stop.

- **The condition held on lines.** ponytail wrote 4.3 fewer lines per task than the baseline (-10.0%, 2SE 1.8). The cut came from `tmpl-fe-stepper` (-10.0, 2SE 1.5) and `tmpl-fe-copy` (-7.3, 2SE 7.1); both backend tasks were equal.
- **It did not hold on tokens or cost.** Pooled, ponytail used +2.9k tokens (+5.8%, 2SE 4.8k) and +$0.003, both noise. On `tmpl-be-recent` it used more tokens (+12.2k, 2SE 11.0k) and cost more (+$0.032, 2SE $0.029), and on `tmpl-be-rename` it used more tokens (+4.2k, 2SE 4.0k).
- **exo against the baseline.** exo used +7.7k tokens (+15.3%), beyond 2SE 6.1k; its cost difference of +$0.016 is noise (2SE $0.017), and its line difference of +0.2 is noise.
- **SubagentStart is a usable hook.** Claude Code's hooks reference (`code.claude.com/docs/en/hooks.md`) confirms that its matcher filters on agent type and that `additionalContext` lands in the subagent's own context.
- **The fit attempt failed.** The current injected body is 2069 bytes, equal to the lock. A short ladder that keeps every rung's meaning takes 423 bytes, and a minimal one that drops parts of three rungs takes 333. Cuts to the existing text that keep its meaning saved 116 bytes, and harder cuts at the edge of meaning saved 164. The best combinations still exceed the lock: safe cuts with the full ladder reach 2378 bytes (309 over), safe cuts with the minimal ladder 2288 (219 over), and harder cuts with the minimal ladder 2240 (171 over).
- **Outcome: stopped.** No exo change was made, and the exo-only rerun that would have measured the inlined ladder did not run.

## Limitations

- n=3 per task and arm, so only large per-task differences clear 2 standard errors.
- All 36 of 36 cells were correct, so correctness cannot discriminate between the arms on these tasks.
- ponytail's line cut came from the two frontend tasks only; on the two backend tasks its lines matched the baseline, so the pooled -10.0% rests on half the tasks.
- Raw cells sit in `benchmarks/runs/2026-10-06-rivals/`, which is git-ignored.
