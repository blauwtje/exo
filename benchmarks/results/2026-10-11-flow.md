# exo flow benchmark: the four-task plan on the inline route, 2026-10-11

Measured on one plan, `docs/plans/text-helpers.md`, which has four tasks: `slugify`, `title-case`, `truncate` and `initials`. Three arms, Sonnet 5.5 (`claude-sonnet-5-5`) at effort high, 4 runs per arm, 12 cells in 4 rounds of 3 cells (`benchmarks/runs/2026-10-11-flow-r1` to `-r4`). Claude Code 2.1.296. No cell timed out, none exited non-zero and none is missing.

- `flow-c7`: exo. Prompt: "Load the exo:build skill and run the plan docs/plans/text-helpers.md. Commit on a new branch feat/text-helpers; push nothing and open no pull request."
- `flow-session`: exo with the `session-build` plugin variant (build's direct loop swapped, see `benchmarks/variants.mjs`). Same prompt as `flow-c7`.
- `flow-base`: no plugin. "Implement every task in docs/plans/text-helpers.md." in place of the first sentence.

All prompts end with "Nobody can answer a question during this run."

```bash
# per round i = 1..4, one cell per arm
node benchmarks/sweep.mjs --set flow --confirm --out benchmarks/runs/2026-10-11-flow-r<i>
# aggregate
node benchmarks/flow-report.mjs benchmarks/runs/2026-10-11-flow-r1 benchmarks/runs/2026-10-11-flow-r2 benchmarks/runs/2026-10-11-flow-r3 benchmarks/runs/2026-10-11-flow-r4
# token type, call count and context size
node benchmarks/split.mjs benchmarks/runs/2026-10-11-flow-r1 benchmarks/runs/2026-10-11-flow-r2 benchmarks/runs/2026-10-11-flow-r3 benchmarks/runs/2026-10-11-flow-r4
```

`score.mjs --publish` cannot read flow runs, because a flow `meta.json` has no `arms`. This file is written by hand from `flow-report.mjs`, `split.mjs` and each cell's `record.json`.

Plugin commit: not recorded. No `meta.json` or `record.json` of the four rounds names it. The `flow-c7` cells load the plugin from the checkout the sweep ran in, so the commit is whatever that checkout held at the time.

`Landed` is the count of plan tasks whose commit is on `feat/text-helpers`, summed over the 4 runs (16 possible). `Hidden check` is the number of runs where `benchmarks/flow-check.mjs` finds no defect; it runs the 17 tests in `benchmarks/flow-hidden/` against the branch's modules. `Tokens` is weighted input plus output from the cell's `usage.json`. `Cost` is `costUsd` from `record.json`. `Cost per success` is the arm's total cost divided by its hidden-check passes. `Wall` is `wallMs`. `Lead peak` is the largest context of any lead call. Tokens and wall are the mean over the 4 runs, with the sample standard deviation where shown.

Per cell, `flow-c7` used 1.76 times the weighted tokens of `flow-base` (93,987 against 53,441, so 76% more), 1.49 times the cost and 1.28 times the wall time. `flow-session` used 1.85 times the tokens, 1.56 times the cost and 1.27 times the wall time. Total spend of the 12 cells was $2.03.

The pass-rate difference (exo minus baseline) is 0.000. The decision rule of the 2026-10-07 run needs exo to beat the baseline by more than 2 standard errors, and both arms are at 4/4, so exo is not better on the hidden check.

## Finding

exo and the baseline both land 16/16 tasks and pass the hidden check 4/4. In these runs exo costs about 76% more weighted tokens, 49% more money and 28% more wall time than the baseline. Every exo cell took the inline route and ran verify; none dispatched a branch review. `flow-session` is within noise of `flow-c7` on every measure.

## Inline verify, earlier rounds v1 to v3

From the changelog, raw cells not kept. The rounds that tested the inline-verify shortcut (commit `91fbda48`, "verify straight from the inline route's steps") ran in a worktree that no longer exists, so their cells are gone. The only record is the `0.126.0` entry in `CHANGELOG.md`:

> On the inline route, `build` now runs `verify.mjs` once when the last task lands, with no `exo:verify` load, no tail reference read and no `--reviews-only` run [...]. One 4-task flow run dropped from 15 to 13 calls and from 94.0k to 87.5k weighted tokens, hidden check passing.

So the changelog gives one before and one after: 15 calls and 94.0k weighted tokens, then 13 calls and 87.5k, with the hidden check passing. It gives no figure for v1, v2 or v3 separately, and this file does not break them out.

The 94.0k and 15 calls match the mean of the four `flow-c7` cells above (93,987 weighted tokens, 15 calls). The changelog does not say which runs it compared, and which side of `91fbda48` the r1 to r4 cells ran on is not recorded, so this is a coincidence of figures and not a link. The 87.5k, 13-call run is not among the rounds r1 to r4 (the lowest `flow-c7` cell here is 84.8k, in r3).

## Limitations

- n=4 per arm and one plan. A mean of 94.0k with a standard deviation of 9.5k, against 53.4k with 4.5k, is a clear gap in this sample, but it says nothing about other plans.
- The plan pastes the code for every task, so the baseline can copy it and has nothing to decide. The plan has four tasks, which is the largest size that takes the inline route.
- The hidden check is the only quality measure, and all arms pass it. It cannot separate arms that all copy the plan's code. It does not score commit format: the baseline's commits carry `Plan-task` trailers (4/4) and exo's do not (0/4), and the check ignores this.
- No branch review ran in any cell, so the cost of review and fixing is not in these numbers.
- The plugin commit of each round is not recorded, and the earlier v1 to v3 cells are gone, so the inline-verify figures cannot be re-checked.
- Concurrency of the sweep is not recorded in the cells. Wall time may include contention between the 3 cells of a round.
- The raw cells under `benchmarks/runs/` are git-ignored, so this file is the record.
