# exo flow benchmark: a four-task plan against a no-plugin baseline

Measured on one plan, `docs/plans/text-helpers.md`, which has four tasks: `slugify`, `title-case`, `truncate` and `initials`. Arms `flow-c7` (exo) and `flow-base` (no plugin), Sonnet 5 (`claude-sonnet-5`) at effort high, 5 runs per arm, concurrency 2, 10 cells in 5 rounds. Claude Code 2.1.292. The `flow-c7` prompt is "Load the exo:build skill and run the plan docs/plans/text-helpers.md. Commit on a new branch feat/text-helpers; push nothing and open no pull request." The `flow-base` cell runs without `--plugin-dir` and gets "Implement every task in docs/plans/text-helpers.md." in place of the first sentence. Both prompts end with "Nobody can answer a question during this run." No cell timed out and none is missing.

```bash
caffeinate -i bash /tmp/flow-run/run.sh
# per round i = 1..5
node benchmarks/sweep.mjs --set flow --confirm --concurrency 2 --out benchmarks/runs/2026-10-07-flow-r<i>
# aggregate
node benchmarks/flow-report.mjs benchmarks/runs/2026-10-07-flow-r1 benchmarks/runs/2026-10-07-flow-r2 benchmarks/runs/2026-10-07-flow-r3 benchmarks/runs/2026-10-07-flow-r4 benchmarks/runs/2026-10-07-flow-r5
```

`run.sh` stopped before a round if the spend so far plus the last round's cost would pass $12. It never stopped.

`Landed` is the count of plan tasks whose commit is on `feat/text-helpers`, summed over the 5 runs (20 possible). `Hidden check` is the number of runs where `benchmarks/flow-check.mjs` finds no defect. The check runs the 17 tests in `benchmarks/flow-hidden/` against the branch's modules. `tests/benchmark-flow-check.test.mjs` proves it: the seed fails and the reference solution passes. `Tokens` is weighted input plus output from the cell's `usage.json`. `Cost` is `costUsd` from `record.json`. `Wall` is `wallMs`. Tokens and wall are mean ± sample standard deviation over the 5 runs, computed from the records. Cost is the mean per cell.

The decision rule was fixed before the run. exo counts as better only if its hidden-check pass rate beats the baseline's by more than 2 standard errors of the difference.

## Results

| Measure | flow-base | flow-c7 (exo) |
|---|---|---|
| Tasks landed | 20/20 | 20/20 |
| Hidden check | 5/5 | 4/5 |
| Defects | 0 | 1 |
| Tokens | 137.0k ± 2.3k | 695.8k ± 70.7k |
| Cost per cell | $0.314 | $1.701 |
| Wall | 95s ± 4s | 488s ± 87s |

Verdict: not better. The pass-rate difference (exo minus baseline) is -0.20 and 2 standard errors are 0.36, so the gap points the wrong way and is not distinguishable from noise at n=5.

Spend by arm: baseline $1.57, exo $8.50, total $10.07. Per cell, exo used about 5.1 times the tokens, 5.1 times the wall time and 5.4 times the cost of the baseline.

## The failed exo cell

Round 2 failed one of the 17 hidden tests, `truncate returns only the dots when max is 3`, which expects `truncate('hello', 3) === '...'`.

The plan pastes the code for each task. The `truncate` code is `if (text.length <= max) return text;` followed by `return text.slice(0, max - 3).padEnd(max, '.');`. It passes the failing test, because `slice(0, 0)` is `''` and `padEnd(3, '.')` gives `'...'`. It does have a real bug for `max < 3`: the negative slice end counts from the end of the string, so `truncate('hello', 2)` returns `"hell"`. The hidden tests do not pin that case.

What happened in round 2:

- The four build-task agents committed the plan code unchanged and the lead landed all four.
- `verify` ran with `--check-command "npm test"` and passed.
- The `review-branch` agent probed `truncate('hello', 2)`, found the `max < 3` bug and returned `Verdict: FINDINGS`.
- The `fix-review` agent added `if (max <= 3) return text.slice(0, max);` to `src/truncate.js`. For `max == 3` that returns `'hel'`, not `'...'`. The correct guard is `max < 3`.
- The fixer ran only the plan's own `src/truncate.test.js`, which covers max 8 and adds no case for the guard. The lead re-ran the gate (green) and committed the fix as a fifth commit.
- Nothing reviewed the fix.

Rounds 3 and 5 also ran `review-branch` and returned CLEAN, because neither review probed `max < 3`. Rounds 1 and 4 got no review (see the caveats). The baseline copied the plan code verbatim in all 5 rounds and passed.

## Where exo's extra cost went

The analysis read the five exo transcripts. Weighted tokens were 590k to 786k per exo cell against 134k to 140k for the baseline, and wall time was 371s to 563s against 92s to 101s.

- **Baseline shape.** 25 lead turns, no subagents: read the plan, `git checkout -b feat/text-helpers`, then for each task write a test, run it red, write the module, run it green and commit. A final `npm test` closes the run.
- **exo lead turns.** 46 to 56 per cell. The lead context peaked at 78k to 93k tokens and was re-read on every turn. By the analysis's weights the lead is the larger share, about 460k to 600k tokens per cell.
- **Subagents.** Each cell dispatched four `build-task` agents in parallel (11 to 16 turns, about 35k to 70k tokens each, 175k to 300k in total). Rounds 2, 3 and 5 added a `review-branch` agent, and round 2 a `fix-review` agent.
- **Sequential landing.** After the parallel build wave (about 60s in round 2) the lead landed the tasks one at a time: `land-task.mjs`, a cherry-pick, a worktree removal and a diff save per task. That took about 100s and 15 to 20 lead turns. Setup before the first dispatch took about 47s and 10 turns.
- **Stop-hook proof-check.** The hook demands a "Proof:" line backed by a product command run in the same turn. The library has no product entry point, so the hook rejected `npm test` and an earlier `verify.mjs` run. It fired 4 times in round 1 and 5 times in each of rounds 2 to 5. Each rejection costs one re-run and one more lead turn at 80k to 90k context. In the analysis's timelines the retries took about 100s to 190s of a cell and 8 to 12 turns, 25% to 35% of the lead's turns.

## Caveats

- **The plan pastes full code.** Copying it scores perfectly, so the baseline had nothing to decide. The hidden check pins only cases where the plan's code is already right, so it cannot reward fixing the `max < 3` bug. Any review and fix that touches `truncate` can only lose on it.
- **The plan has no success criterion.** It has `## Final verification` and no `## Success criterion`, so `verify.mjs` defaults to `npm run check`, which the seed's `package.json` does not define. Rounds 1 and 4 stopped at `FAIL success-criterion` with no review. Rounds 2, 3 and 5 passed `--check-command "npm test"` and reached review. A repository with a check script would not hit this. It means only 3 of 5 exo cells were reviewed, and the round 2 failure comes from exo's own fix, not from the harness.
- **Trailer count not used.** The record shows `Plan-task` trailers on 4 of 4 baseline commits and 0 of 4 exo commits, because `land-task` commits carry none. This measures commit format and not correctness, so the decision rule ignores it.
- **The proof-check hook inflates exo's cost here.** It fires in headless `claude -p`, and a plan with no product entry point turns it into 4 to 5 retry loops per cell. The baseline has no equivalent.
- **Sample size.** n=5 per arm and one failure. A 4/5 against 5/5 split needs far more runs to separate.
- **Setup differences that do not bias the check.** The check exports `refs/heads/feat/text-helpers`, which both arms create. exo's wave worktrees are removed before the end. Budget ($25) and timeout (120 minutes) were not binding: the largest cost was $1.92 and the longest wall time 563s. Rounds 1 and 2 each logged one sandbox denial for the exo lead, with no effect on the result.

## Cost

The run cost $10.07: $8.50 for the five exo cells and $1.57 for the five baseline cells. Per-cell exo costs ranged from $1.44 to $1.92.
