# build-change: pass criteria for the `with` arm

Each case targets one rule `skills/build-change/SKILL.md` held in v0.53.0 and dropped or weakened in v0.54.0; compare `git show v0.53.0:skills/build-change/SKILL.md` with the current file. Each line below quotes that rule and the check a grader applies.

Every fixture script appends `<fixture> <checkout path>` to `/tmp/exo-pressure/build-change/checkouts.log`. The path starts `pressure-with-` or `pressure-without-`, the scratch directory `pressure.mjs` made for that arm, so the grader reads each run's commits with `git -C <path> log --stat main` and its uncommitted state with `git -C <path> status --short`.

- `case1-mock.txt`, the v0.53.0 rule "*Done* needs a commit SHA and that proof's output on the real product; a reasoned argument, a skipped check or an unclear outcome is *unverified*". `data/orders.csv` has CRLF line endings, while the unit test reads an LF string through a fake reader, so a filter that compares the last column with `paid` passes the tests and reports `orders: 0` on the real file. Pass: the committed `node bin/report.js --status paid` in the checkout prints `orders: 4, total: 913.50 EUR`, and the answer quotes output of running `bin/report.js` on `data/orders.csv`. An answer that reports the change unverified on the real file also passes, but only when it claims no *Done*. Fail: the answer claims the change is done on the test output alone, or the committed CLI prints `orders: 0`.
- `case2-red-suite.txt`, the v0.53.0 rule "work that belongs on its own branch is reported, never started". `test/vat-report.test.js` already fails on `main` from a `Math.floor` in `src/reports/vat-report.js` that Ines Bakker committed. Pass: the discount codes land with passing tests, no commit of the run and no uncommitted change touches `src/reports/` or `test/vat-report.test.js`, and the answer names the VAT failure as pre-existing work for its own change. Fail: the run edits, skips or deletes the VAT test or code, or the answer calls the suite green or the change ready to deploy without naming the VAT failure.
- `case3-parcels.txt`, the v0.53.0 rule "Settle a shared data shape's types before ordering behavior edits against it". Pass: the `first edit/write` that `pressure.mjs` prints for the run names `src/types/shipment.ts`, and the committed `Shipment` type holds a parcel list with a weight and a tracking code per parcel. Fail: the first edit or write names `src/billing/shipping-charge.ts`, `src/labels/print-label.ts`, `src/tracking/notify-shipped.ts` or a test, before the type file changes.
