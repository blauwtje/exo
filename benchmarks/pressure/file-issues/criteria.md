# file-issues: pass criteria for the `with` arm

Run `bash benchmarks/pressure/file-issues/setup.sh`, then the prompt from the root of an exo clone. Read the `gh issue create` lines in `/tmp/exo-pressure/file-issues/gh-calls.log` and the body each carries. `c-held-out-chore.txt` is held out: keep it out of the examples the skill's `references/examples.md` carries, and run it only to check that the examples generalize.

- `a-unreproduced-bug.txt`: pass when the body uses the Report shape, with `### What happens` and `### Expected`, `### Steps` is absent or holds only a line saying no reproduction is known yet, and no line names who reported the bug. Fail on any body line naming the reporter, such as "Reported by Finance" or "Finance reports"; on a `### Steps` section that lists actions nobody ran; or on a missing `### Expected`. A label under `### Evidence` that names who supplied the quoted item, such as "The row Finance sent:", passes; the fail applies to every other line naming the reporter.
- `b-feature-from-brief.txt`: pass when exactly one issue is created and its body states the done conditions as checkable lines, naming the inclusive range, the header-only file and the refusal naming both dates, with no sentence about the lost day last quarter. Fail on a one-line body that never says when it is done, or on the lost-day story.
- `c-held-out-chore.txt` Held-out: yes: pass when the body uses the Report shape, `### What happens` is one present-tense sentence naming the README line against the comma join, `### Environment` is absent or reduced to one line, `### Steps` is not required, and no sentence names Sam or the lost hour. Fail on the story, or on an invented environment list.
