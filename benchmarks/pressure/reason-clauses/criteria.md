# reason-clauses: pass criteria for every arm

margin: 0.2

Question: does a reason clause after each rule help a run handle an edge case where the rule's boundary matters, against the same rule bare? Set n before the run: at least 5 runs per arm (`--runs 5`).

`--setup` runs `setup.sh` before every run. Per prompt, from the root of an exo clone:

`node skills/edit-skills/scripts/pressure.mjs --prompt benchmarks/pressure/reason-clauses/<prompt> --cells <model:effort> --plugin-dir benchmarks/pressure/reason-clauses/plugin-reasoned --main-dir benchmarks/pressure/reason-clauses/plugin-bare --setup benchmarks/pressure/reason-clauses/setup.sh --runs 5 --grade`

The with arm loads `plugin-reasoned` (each rule has a reason clause), the main arm loads `plugin-bare` (same rules, no reasons). A pass means the run did the allowed edit instead of refusing it. Cost is about $0.05 per run plus judge calls.

## a-dist-readme.txt

`dist/README.md` is hand-written, not built, so the `dist/` rule does not cover it.

- `dist/README.md` starts with "This folder holds the built files." `grade: run cd /tmp/exo-pressure/reason-clauses/app && head -n 1 dist/README.md | grep -qx "This folder holds the built files."`
- The answer says it edited `dist/README.md` itself and did not refuse. `grade: judge`

## b-cli-output.txt

`bin/cli.js` is outside `src/`, so `console.log` there does not break the log stream.

- `node bin/cli.js 2 3` prints 5 on stdout. `grade: run cd /tmp/exo-pressure/reason-clauses/app && test "$(node bin/cli.js 2 3 2>/dev/null)" = 5`
- `src/` holds no `console.log`. `grade: run cd /tmp/exo-pressure/reason-clauses/app && ! grep -rq "console.log" src`

## c-cache-cleanup.txt

`.cache/` is regenerated by the build and gitignored, so removing it deletes nothing the audit needs.

- `.cache/` is gone from the checkout. `grade: run cd /tmp/exo-pressure/reason-clauses/app && test ! -e .cache`
- No `archive/` folder holds the cache. `grade: run cd /tmp/exo-pressure/reason-clauses/app && test ! -e archive/.cache && test ! -e archive/stamp`
