# Contributing

## Set up

Clone the repository and run `npm install` once. You need Node 22 or newer and `bash` on `PATH`; the verifier and tests use only the Node standard library.

A marketplace added from `blauwtje/exo` on GitHub installs a cache copy, so an edit there is live only after a release; `claude --plugin-dir <your clone>` runs the working tree instead. A marketplace added from a local directory whose `marketplace.json` sets `"source": "./"` (this checkout is one) loads the plugin in place, with no cache copy: an edit is live after `/reload-plugins`.

## Checks

| Command | What it runs |
|---|---|
| `npm run check` | The gate before any commit: the verifier with the script tests, the same run as `npm run validate`. `verify.mjs` starts the script tests first and runs the other checks while they run, then reports the test result in its usual place. |
| `npm run validate` | The structural checks over the skill corpus and the script tests. |
| `npm run validate:static` | The structural checks only, no script tests. |
| `npm run check`, `npm run validate:static` | The `edit evidence` check fails a branch whose commits since the merge base with `origin/main` change `skills/*/SKILL.md`, `skills/*/references/*.md`, `agents/*.md`, `hooks/session-routing.md`, `hooks/session-rules.md`, `hooks/dispatch-rules.md` or `harnesses/codex/host-note.md` without an `Evidence:` trailer on any commit: a `benchmarks/results/` or `benchmarks/pressure/` file added or changed in that range, or `none (<reason>)`. On any range it also fails an `Evidence:` line that is malformed, even with no wording change. It is `UNRUN` without a merge base. |
| `npm run check`, `npm run validate:static` | The `test timing` check fails a `tests/*.mjs` assert that compares one raw elapsed value (`Date.now() - start`, `performance.now() - start`, `process.hrtime.bigint() - start`, or a variable set from one) to a number literal, because a loaded machine breaks the bound. Compare two timed runs instead, or start the assert message with `timing-ok:` and a reason. It reads one line per assert. |
| `npm run check`, `npm run validate:static` | The `covering tests` check fails when `coveringTests` in `lib/covering-tests.mjs` no longer maps `agents/run-unit.md` to `tests/agents.test.mjs`, the pair `land-task` relies on to run the tests that read a changed file. |
| `npm run check`, `npm run validate:static` | The `boundary rows` check fails when a `Boundary:` line in `docs/specs/*.md` names a test file on disk that holds no test whose title contains `out-of-scope`. A named file not on disk is skipped. |
| `npm test` | The script, hook and benchmark tests under `tests/`. |
| `npm run smoke` | A real session that lists the `exo:` skills. It calls a model. |
| `claude plugin validate .` | The harness's own manifest check. |
| `npm run generate` | Writes the gitignored `harnesses/codex/generated/` from the sources, for inspection only (see [Codex](#codex)). |
| `node install.mjs [--harness claude,codex] [--scope user\|project\|local] [--project <dir>] [--yes] [--update] [--remove]` | Installs exo into every detected harness from this clone, or updates or removes what it recorded. It generates in memory, so an install never uses a stale tree. |
| `node verify/skill-graph.mjs <command> [args]` | A read-only index over skills, agents, hooks, root docs, `verify/` and `tests/`: `size`, `range`, `inbound`, `pins`, `refs`, `overlap` and `json`, each printing a compact answer instead of a whole file. |

CI runs `npm run check` on Node 24 on Ubuntu for every push to `main` and every pull request.

`npm test` prints Node's spec reporter, which marks a failure with `✖`. `npm run check` runs the same tests through TAP, so its failure line names each failing test as `not ok`. Both load `tests/clean-run-env.mjs` first, which strips the run variables `EXO_RUN`, `EXO_RUN_DIR`, `EXO_RUN_TASK`, `EXO_RUN_SESSION`, `EXO_DROPS` and `EXO_PENDING_EVIDENCE`, so a test inside `exo run` never parks gates in the live run.

The `instruction density` check fails a list item of three or more sentences and a sentence over 40 words in the Markdown under `skills/`, `agents/` and `output-styles/`, outside fenced code, frontmatter, HTML comments, headings and tables; an inline code span counts as one word. `verify/instruction-density-allowlist.txt` names the offenders the tree held when the check began, and `INSTRUCTION_DENSITY_ALLOWLIST_LOCK` in `verify/budgets.mjs` caps its length. A line that no longer matches stays until `node verify/instruction-density.mjs --prune` drops it; the command never adds a line and prints the new count to copy into the lock.

The `boundary words` check compares each `.md` file under `skills/`, `agents/`, `rules/` and `hooks/` that exists at the merge base with `origin/main` and in the working tree, counting `only`, `not`, `no`, `never`, `every`, `each`, `all`, `full`, `except` and `unless` as whole words, and fails when a count falls; it is `UNRUN` without `origin/main` or a merge base with it. A deliberate drop is named as `Drops: <word> in <path>[, <word> in <path>]`, in a plan task's field line (land-task passes it to the land gate as `EXO_DROPS` and copies it into a compact task's commit body) or in a commit body since `origin/main`.

The `git whitespace` check runs `git diff --check` from the merge base with `origin/main` to the working tree, so committed, staged and unstaged changes are all covered; without a merge base it checks the working tree only. It also scans untracked files for trailing whitespace.

The `derivation` check fails when a name exo does not own reaches a shipped file, or a third-party notice file appears at the repository root. `LICENSE` is the whole licence. The names sit base64-encoded in `verify/checks/derivation.mjs`, because a plaintext list would be the text the check forbids. `plan-check.mjs` scans a brief that targets this repository for the same names and names each with its line, so a plan is reworded before its first land gate.

The `fix-class load` check fails once per repair text that does not name `fix-class.md`: `agents/fix-review.md`, `skills/build/review-fixer-prompt.md`, the `## Shared block` of `skills/find-cause/fixer-prompt.md` and `agents/build-task.md`. A new repair agent text joins `REPAIR_TEXTS` in `verify/checks/fix-class-load.mjs`.

The `script help` check fails a `skills/*/scripts/*.mjs` entry point, a file with a shebang or an `isMain` call, that has neither a `--help` comparison (`===`, `includes`, `case`) nor a `parseFlags` call passed `usage`. It reads source and runs no script.

## Editing a skill

Load the `edit-skills` skill before any skill or delegate-prompt edit; it holds the shape and size rules the verifier enforces. `verify/budgets.mjs` names the skills the full verifier checks; every other skill still passes the frontmatter, portable-language, description-budget, body-budget and reference-shape checks. Add a skill there once it reaches that shape.

A skill whose work leaves the machine (a push, pull request, merge or issue) runs only on the authorization its body names: the user's pick of a finish route or a plain request. The one exception is `ship` under `ship=ask`, which pushes a non-default branch to origin without asking; merge, default-branch push, pull request and issue still ask. It never deletes a branch or cuts a release.

Twelve skills carry `disable-model-invocation: true`, because only the user should start them: `start` and `route-skills` show the skills on request (the session hook already loads the routing rules); `save-session` and `remember` write a record only the user should approve; `run-plan` hands the plan to `build`, or installs the terminal `exo run` with `setup`, `prompt` runs a rewrite only after the user approves it, and `improve` runs a loop that edits code until the user stops it; `configure`, `edit-skills`, `file-issues`, `write-docs` and `check-docs` start from a person's request and no other skill or agent invokes them, so they carry no routing prompts. Every other skill stays model-invocable so a next-stage answer can start it, and its description opens with `Use when`.

`ABOUT.md` says what exo is and lists exo's domain words with the synonym each replaces. Skill bodies, replies and commits use the left column; the `derivation` check reads the file for names exo does not own.

A new skill needs all of: the folder `skills/<name>/`, its name in `EXPECTED_SKILLS` in `verify/budgets.mjs`, a reference contract in `verify/checks/reference-tables.mjs`, room for its description in `DESCRIPTION_TOTAL_LOCK` and `DESCRIPTION_TOTAL_WARN`, and a page under `docs/skills/`. Write a skill from a discipline you have read, never from a one-line description.

Grade a pressure case with `node skills/edit-skills/scripts/pressure.mjs --grade`: it scores each run pass or fail against the tagged lines of the case's `criteria.md`, applies `--threshold` over the runs (1 run and 1 judge vote by default, 3 each under `--full`) and reports the with-minus-without delta; `--contrast-style <a>,<b>` compares two output styles and prints `WRONG STYLE` when a run's init event reports another; see `benchmarks/pressure/README.md`. It never runs in `npm run check` or `npm test`.

Rename a skill with `node skills/edit-skills/scripts/rename-skill.mjs --from <old> --to <new>`. It moves the skill folder, its `docs/skills/` page and its pressure folder, then rewrites every word-bounded mention outside `CHANGELOG.md` and `benchmarks/results/`.

A `SKILL.md` body after its frontmatter stays within `SKILL_BODY_TOKENS.ceiling` in `verify/budgets.mjs`, counted as bytes / `BYTES_PER_TOKEN`, because a body is paid for on every run; bulk lives in `references/` and the body names the step that opens it. A reference longer than `REFERENCE_CONTENTS_LINES` opens with a contents list linking each `##` section, and no reference links to another. `PENDING_TRIM` lists the skills not yet trimmed to these. Split a skill in two only when the halves fire at different moments, because each skill adds its trigger to every session's listing.

## Adding a setting

A new setting is one entry in `skills/configure/schema.json` plus the matching `userConfig` entry in `.claude-plugin/plugin.json`.

`docs/` is git-ignored: research notes, specs and plans live outside the repository.

`docs/principles/README.md` indexes Anthropic's engineering principles; the `principles` check fails a page that is undated, unsourced, unmapped or over budget, fails a backticked path cite after `exo:` unless it names an existing file or folder exactly, so any `:` or `#` tail fails, and an anchor span after one space (at least 2 identifier characters, text that must occur in the file; a folder cite takes none) that is gone, and warns when its `Checked:` date is older than `EXO_PRINCIPLES_STALE_MS` (90 days). The index states the value rule: a hook, check, agent, review, model tier or retry stays only when its value is at least its cost in tokens, time and false blocks, and an unsure case gets a `benchmarks/speed-ledger.jsonl` line.

## Benchmarks

`benchmarks/README.md` covers the routing eval of `benchmarks/routing.mjs`, whose recorded result the `routing` check compares with the skill descriptions and `hooks/session-routing.md` (a change to either needs a rerun), the paired headless runs that measure exo against a session without it, and the `replay` set of `benchmarks/sweep.mjs`, whose `flow-unit` cell is prepared with the compact unit-route plan (`compactPlan`) and `flow-c7` with the code plan, and which replays past branch and fix-diff reviews per model, plus the ideas set of `benchmarks/ideas.mjs`, which scores the originality and variety of the design options `spec` offers, plus the build-loop review replay of `benchmarks/review-replay.mjs`, whose quick tier (2 tasks x 1 run, under $1) is the default and whose full tier runs behind `--full`, plus the $0 `benchmarks/lead-context.mjs`, which profiles each lead session's context from local transcripts: peak tokens, turns past the soft and hard limit, compaction points and the share of added context per stage.

Two quick tiers screen a change for under $1.00 by running only the exo arm against a stored stock arm: `node benchmarks/run.mjs --tier value` runs 3 fixed value tasks against the stock rows stored by `node benchmarks/run.mjs --tier value --stock-baseline`, and `node benchmarks/improve-speed.mjs <checkout>` runs one `flow-unit` cell against the pooled base arm. `--dry-run` prints the projected cost first; `--full` on either restores the complete measurement. `benchmarks/README.md` has the tier table.

The hand-run benchmarks `routing.mjs`, `ideas.mjs`, `improve-all-score.mjs`, `sweep.mjs`, `checkpoint-fork.mjs`, `pressure/drive.mjs`, `replay/grade.mjs` and `skills/edit-skills/scripts/pressure.mjs` run a quick tier by default (a small fixed case set, one run, deterministic checks before any judge, a stored baseline) and spend nothing under `--dry-run`; `--full` runs the full case set and repeats, and `routing.mjs --full` alone writes the recorded `routing.json` the `routing` check reads. `lean-gates.mjs` and the tbench runner have no `--full`; `benchmarks/README.md` lists each command.

The build-speed idea ledger is `benchmarks/speed-ledger.jsonl`, one JSON line per idea sorted by `id` with every key of `KEYS` in `benchmarks/speed-ledger.mjs`. `benchmarks/speed-ledger.md` is generated from it: add or change a line, then run `node benchmarks/speed-ledger.mjs --render`; `node verify.mjs` runs the same check, static mode too, one FAIL per problem; `node benchmarks/speed-ledger.mjs --index` prints only the `## Index` section; `node benchmarks/speed-ledger.mjs --check` exits 1 and lists each problem (md differs from the render, repeated `id` or `fingerprint`, bad `verdict`, unknown `related` id, missing `results` path, line missing a key).

`node benchmarks/adhd-score.mjs` with no flag runs the quick repo-style eval of `exo:adhd` on the 10 cases in `benchmarks/adhd/quick.json` once each, capped at $0.30 (`--max-usd` overrides) and meant to finish under 60 s, and prints the median output-token ratio against an "Answer concisely." arm plus answer-in-first-line %, clean-deliverable %, question-last % and facts-kept %; `--concise-baseline` stores that reference arm in `<git common dir>/exo/adhd/concise.json` (`--all` rebuilds every case) and the quick run needs it; `--arm caveman` swaps the measured arm for the caveman reference style in `benchmarks/adhd/arms/caveman.md`; `--full` or any full-run flag (`--screen`, `--baseline`, `--rescore`, `--resume`, `--ablate`, `--runs`) runs the full score below, and `--arm` cannot combine with them.

`node benchmarks/adhd-score.mjs --full` prints the adhd output-style score, the mean per-case ratio of `exo:adhd` to default-style output tokens (lower is better; gates: no prose after the last `?`, plus a `?` when the case sets `ask`, a pure deliverable when the case names a `deliverable` pattern, and one literal per required fact of an explain request; a run that fails a gate scores max(1, ratio), and a run that misses m of n facts moves that far toward it by m/n); stderr lists each case's visible tokens and billed output tokens (adhd/default), then the billed totals, which the JSON log keeps as `billedTokens` and `baselineBilledTokens`; `--baseline` stores the default-style reference for the cases missing from `baseline.json`, saving after each case (`--baseline --all` rebuilds every case), `--check` compares the stored `baseline.json` with the cases and `--calibrate` compares the facts judge with your labels from `--to-label` and the known-FAIL rows from `--add-fail-labels`, `--stability` measures how often the facts judge flips on the same reply, `--dry-run` prints the projected cost before any call and, when it exceeds `--max-usd`, an over-budget line on stderr with exit 0, `--screen` skips the saturated cases and runs the adhd arm once, `--cases a,b` limits the run to those case ids, `--rescore --log <file>` re-judges the stored replies of a log with no reply calls, `--resume <partial log>` continues a partial run in a new log, and `--max-usd` caps spend (the adhd arm runs 3 times per case and the cap is $3 by default; `--runs` and `--max-usd` override). `baseline.json` and `labels.jsonl` live in `<git common dir>/exo/adhd/`, shared by all worktrees and never committed.

`benchmarks/baseline-pool.mjs` pools baseline arms by a sha256 content key of the arm's loaded files at its commit plus cell, model, effort and Claude Code version, never the commit hash. Subcommands `key`, `lookup`, `add` and `replay`; the store is `benchmarks/baseline-pool.jsonl`, one row per arm. It serves `cost` and `tokens` only and exits 2 for `wall`. `replay` reads the per-run base rows of rounds 2-8 (rounds 7-8 are copied into `benchmarks/results/2026-10-20-baseline-pool.md`) and exits 0 only when at least one pair of rounds matches and every matched pair has cost and tokens p > 0.05; `benchmarks/sweep.mjs` does not call the pool.

A seeded review cell's measured record carries `hits` (the seeded range overlapped by a `fix` finding, 0 or 1) and `reportHits` (the same overlap by a `fix` or `report` finding), so a judge that only reports the seed still counts; both are null without a parsed report.

## How a skill dispatches work

- Ten roles are plugin agents under `agents/`, because an agent file fixes a tool list and a turn limit, and its body is the system prompt rather than text pasted into every dispatch. A role becomes an agent only when one effort, one tool list and one turn limit fit every dispatch. Each agent's description says what it does.
- `exo:review-branch` runs on the `review-deep` kind's model and effort, passed in the call, when a landed task's `Risk:` field names a security boundary; any other `Risk:` field gets the light reviewer. On scope `branch` it reads `.exo/review-input.md`, which `verify.mjs --reviews-only` writes each round with each landed task's `Red:` lines (the reviewer reads no implementer report), before the plan and the diff. It fixes nothing; on `FINDINGS`, `verify` hands its report to `exo:fix-review`, then runs the Final verification once. From round 2 on (the DISPATCH line carries `ledger=`), the reviewer raises `fix` only inside the fix diff, the commits with no `Plan-task:` trailer, or on an earlier Sweep hit; any other defect is a `report` line, and the `reference tables` check keeps that rule in `## Probe` of `skills/verify/references/review-rules.md` and, anywhere in that file, the rule that `## Red lines` of `review-input.md` is the reviewer's only `Red:` source.
- `lib/model-kinds.json` owns every model and effort: it maps each agent file to a task kind and each kind to a tier and an effort, so this page names neither. A kind's `tier` may be `inherit`, which omits the dispatch's `model` so the session's own model runs. A dispatch that names a model overrides the agent's own. The `doc-task` kind runs at the `standard` `medium` cell, for a task that edits only docs. `run-plan.mjs` runs a task on it when every `Files:` entry is a `.md` file outside `skills/`, `agents/`, `rules/` and `hooks/` and not named `CLAUDE.md`. `agents/run-unit.md` has its own `run-unit` kind, `medium` effort, since it only relays `next-task.mjs` output and dispatches. `run-tail.mjs` runs the overlap review and the fix-diff re-review of a run on `review` and the branch review on `review-deep`.
- The `budget` setting turns the per-kind table in that file on or off: each kind holds one `on` cell with a model and an effort, and `build-task` and `doc-task` also a `retry` cell one level up, which `readKindTable` returns under `retry: true`; every `land-task` refusal except a usage error (`UsageError`) or a plan error (`PlanError`) prints a `Then:` handler line from `lib/refusal-handlers.mjs`, and every one except a code-rule refusal (`CodeRuleError`) ends with a line `exo-retry` after it (an `ENV: <service> down` refusal, raised when a red Proof finds the service down and the one start plus Proof rerun fails to bring it up, prints no `exo-retry`, as a stronger model cannot start a service), and the hook gives a prompt holding that line the kind's `retry` cell, and headless `run-plan.mjs` runs a task's try after a failed attempt on that cell too (`budgetPin`). The `agent-effort` hook sets each dispatch's model and effort from the `on` cell, replacing a model or effort the call passed on an `exo:` agent and naming the replaced value in its hook line; no agent or skill file pins either, and no per-budget twin exists. Under `off` the hook sets neither, so every agent inherits the session. Codex ignores a call's model, so its generator emits one agent per role from the `on` cell. The `budget` schema offers `on` and `off`; its `aliases` map every old value (`fast`, `balanced`, `quality`, `low`, `lean`, `medium`, `normal`, `high`, `full`) to `on` and let `lib/settings-store.mjs` read an old stored name as the new one.
- `next-task.mjs` prints the `input unreachable` handler, not the `plan drift` repair handler, when any drift item is an input path the plan names that this machine cannot read: the run stops `BLOCKED` with that path, since no repair session can supply the input; headless `run-plan.mjs` stops there before any plan or task session, and `agents/run-unit.md` and `skills/build/references/run-loop-direct.md` route each `PLAN DRIFT`, and a `BLOCKED input unreadable` build return, by the printed `Then:` line.
- `unnamed.jobs` in `lib/model-kinds.json` maps a job word to a kind for an unnamed dispatch, in this order: review, verify, audit, judge → `review`; decide, design, choose, pick, cause, diagnose, architect → `hardest`; fix, repair, implement, build → `build`; investigate, research, summarise, summarize, explore → `investigate`; locate, find, lookup → `lookup`; rebase, squash, cleanup → `chore`. Several job words in one description → the first word in table order wins, so design words outrank build words. `readKindTable` rejects a job word naming an unknown kind.
- Every other delegate is the harness's `general-purpose` agent; the dispatching skill passes its model and effort from `lib/model-kinds.json` through a `dispatches` entry and hands it the role text from a `<role>-prompt.md` beside the skill.
- `skills/improve/SKILL.md` dispatches each round worker as a `general-purpose` delegate on the `improve-round` kind (`strong`, `high`), with `skills/improve/references/worker.md` as its role text.
- An agent that takes everything from its dispatch sets `omitClaudeMd: true` (Claude Code 2.1.271 or later) and carries the rule against deleting past a blocked state in its own body, because it loads no `CLAUDE.md`.
- `CLAUDE_CODE_SUBAGENT_MODEL` outranks the named model on Claude Code before 2.1.251.
- The session's effort reaches no subagent: the `agent-effort` hook sets effort at dispatch, and every `dispatches` entry passes a model and an effort in the call. `CLAUDE_CODE_EFFORT_LEVEL` overrides them, so only `exo claude` sets it, for an explicit `--effort` or a provider entry that names an `effort`.
- The stage skills pin no model: a pinned model would override the session's model and rebuild the prompt cache mid-session. Set `model` or `effort` in a skill only where its work always needs that tier.
- A delegate never sees the session hook, and the session text carries no pointer to `lean.md`, so the four delegate prompts and agents that write code read `skills/route-skills/references/lean.md`, or carry lines from it: `agents/build-task.md`, `skills/build/bug-fixer-prompt.md`, `skills/build/review-fixer-prompt.md`, and `skills/find-cause/fixer-prompt.md`. `agents/build-task.md` also reads `skills/route-skills/references/code-standard.md` in its `## Return` step and fixes its own diff against it before `land-task.mjs --check`.

## Verifying in one round

A plan whose tasks all landed passes `exo:verify` in one round, because land catches what verify caught late and a repair is committed and rechecked inside the round.

- **Tests at land**: after the Land gate passes, `land-task.mjs` runs the tests that read the task's changed files and refuses the land, naming the test, when one fails. `lib/covering-tests.mjs` finds them by scanning `tests/*.test.mjs` for a quoted path equal to a changed file or one of its ancestor folders; the `covering tests` check fails when a known pair, such as `agents/run-unit.md` and `tests/agents.test.mjs`, stops matching.
- **Shards**: `verify.mjs` splits the branch diff into shards that each fit one reviewer's context budget and together cover every changed file; a file over budget is split by hunk ranges. Each shard gets its own `DISPATCH Branch <i>/<n>` line and review-input file.
- **Coverage**: `agents/review-branch.md` ends its file with `Read: <paths>`. `merge-reviews.mjs` unions the `Read:` lines, prints `COVERAGE <read>/<total>`, prints `UNREAD-FILE <path>` for each changed file nobody read, and caps the verdict at FINDINGS while one is unread.
- **Boundary scope**: a task with `Risk: security boundary` carries `Boundary: in <inputs> | out <classes> | test <file>`, with `<file>` in its `Files:`, and plan-check refuses it without. `verify.mjs` copies each `Boundary:` line into the review input; a bypass in an `out` class gets weight `out-of-scope`, which `merge-reviews.mjs` does not count. The `boundary rows` check fails when a named test file holds no test titled `out-of-scope`.
- **Branch's own scripts**: when the verified repository is the loaded plugin's own source and the branch changed files under `skills/verify/`, `skills/build/review-fixer-prompt.md` or `skills/route-skills/references/code-standard.md`, `verify.mjs` re-executes the branch's copy of itself. Changed `agents/` files print one `SELF-HOSTED agents=<paths>` line, because agents resolve by name from the loaded plugin.
- **Repair mode**: the fixer commits each repair after its proof, and `verify.mjs --repair` refuses a dirty tree (`FAIL fixer-uncommitted`), a fix count above 0 with no new commit (`FAIL fixer-no-commits`) and a findings file whose hash changed since review (`FAIL stale-findings`). It rechecks only the repair diff: the Land gate, the tests covering the changed files and each named guard, then one fix-diff review. `npm run check` runs once at loop exit. It prints a `LOOP next=fix|done|stop round=<n>/2` line that `skills/verify/references/repair.md` follows.
- **repair-bound**: at most two repair passes per round, counted in `<root>/.exo/verify-state.json`; a third prints `STOP repair-bound` and hands the open findings to the user.
- **Fix class**: every repair fixes the class of its finding, not the one line. `skills/build/references/fix-class.md` says to name the rule the code broke, sweep the repository for it, fix every hit and add the cheapest guard that fails on a new instance. Each repair commit body carries `Sweep: <n> fixed` and `Guard: <file> | none (<reason>)`; `--repair` fails a commit missing either (`FAIL fixer-no-guard`) and a guard outside the repair diff (`FAIL fixer-guard-not-in-diff`). The `fix-class load` check is the guard for the rule itself: it fails when a repair agent text stops naming `fix-class.md`.

## Unattended runs

`node skills/build/scripts/run-plan.mjs <plan.md>` lands a plan with no session open. It and `exo run` start only from a terminal: with `CLAUDECODE` set, as in a Claude Code Bash call, they refuse (`SESSION_REFUSAL` in `run-session.mjs`, exit 2), except `run-plan.mjs --dry-run`; a session builds the plan through `build` with subagents. Each unlanded task runs in a fresh `claude -p` process given `/exo:build <plan> --task <n>`, then one `/exo:verify` process and `verify.mjs` run. `--dry-run` runs the preflight and prints the task order, rules and first prompt without spawning; the script's header comment lists the other flags; `--max-iterations` defaults to twice the unlanded tasks, `--timeout` to 60 minutes per process (`EXO_REVIEW_TIMEOUT_MS` sets a tail review session's limit), `--model` and `--effort` to `agents/build-task.md`.

- **Refusal**: `run-plan: refused: <why>`, exit 2, when the checkout is off the plan's `Branch:`, on the default branch, has a tracked change, or `plan-check --loop` fails, or when `ensureServices` in `lib/services.mjs` finds a service the Proofs need down: a Docker row (compose file or Testcontainers dependency) starts OrbStack or Docker, whichever is installed, and waits `EXO_DOCKER_READY_MS` (default 60 s) for `docker info`, and `node lib/services.mjs --root <dir>` prints the same result.
- **Permissions**: every process runs under `--permission-mode dontAsk`, allowed only `Read`, `Edit` and `Write` in the checkout, the runner's scripts, the plan's `Proof:`, `Run:`, `Land gate:`, `Lint:` and `Allow:` commands, and read-only git, and denied `git push`, `gh`, history rewrites, `git commit`, `git stash`, `git clean`, `git restore`, `settings.mjs` and `memory.mjs`, so `land-task.mjs` is the only committer. Task and plan sessions also deny `Edit` and `Write` of the plan file (`denyRules` in `run-session.mjs`); repair sessions keep plan `Edit`. `EXO_RUN_TASK=<plan-id>/<n>` makes `land-task.mjs` refuse any other plan, task or `--fix`; only `--check` and `--code-rules` may name another task of the pinned plan, and they write no file.
- **Breach check**: after each process HEAD holds no new commit, or one whose parent is the old HEAD and whose only `Plan-task` trailer names the task; no branch ref may move, and no `refs/remotes/*` ref may move unless another session caused it: the run branch's remote-tracking ref must not move, appear or vanish, and no other one may move to a tip holding a commit the run made.
- **Output**: stdout gets one `[mm:ss]` line per event (run start, task start, idle after a sleep gap, landed, plan session done with its one `plan session: <k> tasks landed` line of time, turns, tokens and cost, failed or blocked, run done), then a summary of at most six plain lines ending on `Details: <dir>/summary.txt`; per-task lines, denials, verify lines, reports and manual checks go to `summary.txt`.
- **Stop**: the last line of `summary.txt` is one `run-plan: stop: ` line (`done, <k>/<k> tasks landed, gate PASS|FAIL`, `iteration cap`, `attempt cap <n> reached` (failed attempts in the process reach `attemptCap` in run.json `defaults`, 4), `no progress on task <n> in <k> iterations` (a failed attempt repeats an earlier one of that task: same last failing line and same changed paths), `task <n> blocked`, `breach in iteration <i>`, `exo not loaded` or `stopped by <signal>` (SIGTERM, SIGINT or SIGHUP; the signal listener writes the stop records itself, adds `; land-task: <failing line>` from the current task's newest land-task output, and exits 1 unless a session is live, where the session's own listener ends the claude group and exits)); only `done, <k>/<k> tasks landed, gate PASS` exits 0, a `parked: ` stop (a rebase conflict at review start included: the run aborts the rebase, opens land-run's gate and exits before any review session) exits 3, every other stop exits 1. A command outside the allowlist is denied and counted on stdout and listed in `summary.txt` (each cut to 120 characters), not a stop; the task is judged only by whether it landed, so a run of denials that lands nothing counts toward `no progress`. An interactive command stops the run at the timeout.
- **Logs**: `.exo/run-plan/<plan-id>/<UTC time>/`, one `iter-<k>-task-<n>.log` per process, one `land-task-<n>.log` per task holding every land attempt, plus `tail.log` and `summary.txt`.
- **Sessions and budget**: each session gets a prompt generated from `skills/build/run-task-prompt.md` (a `## Build session` or `## Plan session` section) and loads no skill; a build session runs the plan's `Land gate:` command before it reports the task done, and skips that step when the gate is `none`; `land-task.mjs` runs the gate on a candidate commit that carries `Plan-candidate: <plan-id>/<n>` in place of the `Plan-task:` trailer, so the gate sees the task's own diff, new files and `Evidence:` and `Drops:` trailers; every `land-task.mjs` run (landing, `--check`, `--fix`) first takes the exclusive lock `exo-land.lock` in the checkout's git directory (a dead owner's lock is taken over, `EXO_LAND_LOCK_MS` caps the wait), so a `--check` and a landing take turns; a pass promotes the candidate to a new commit with the `Plan-task:` trailer on the same parent, a failure or crash drops it, and `--check` always drops it, each by `git update-ref` against the candidate's own sha, so a HEAD that moved during the gate refuses with `HEAD moved` and no landed commit is rewritten; a landing then asserts HEAD sits on the commit it started from and holds only `Files:` paths; a passing `--check` writes `.exo/checked-<n>`. While the gate runs, `EXO_PENDING_EVIDENCE` holds the `Evidence:` values of the plan's other unlanded tasks, which satisfy the `edit evidence` check's need for one trailer; proofs and verify run without it. a test that writes outside the run folder fails with EPERM in the sandbox, the session does not rerun it, and land-task's Proof runs it outside the sandbox. `--session auto|task|plan` picks the shape: `plan` builds all unlanded tasks in one session, `auto` (default) picks it for at most four tasks with disjoint `Files:` and no design task, else `task`; `--session plan` refuses when two tasks list the same path. A plan session runs `land-task.mjs --check --task <n>` with the plan report as `--report` before each task's GREEN line, fixes a Lint, Land-gate or code-rule refusal and reruns it, and ends `PLAN DRIFT` on a refusal it cannot fix or the same refusal twice. The Success run, then the review and fix rounds after the build, run by script from `run-tail.mjs`: the Success criterion runs first on the head tree (one `fix` session repairs a red result, a second red result stops the run), and no review starts before it passes; each CLEAN or FINDINGS review verdict is stored with its tree in the check cache, and a resumed run skips the review of an unchanged tree and reuses its report and verdict; the `review done: <name>: <verdict> (<model>, <n> findings)` line in `run.log` names the session's model (`unpinned` when none) and, with a verdict line, its finding count. Each session appends one line to `sessions.jsonl` in the log folder, ending in the session's `model` (the reported one, else the pinned one); `--max-run-usd` caps the sum of their `costUsd` and stops the run with a `budget:` line when spent (`--max-budget-usd` caps one session). Before the review fix session starts, `run-tail.mjs` saves the commit the review saw in the log folder: `pre-fix-head` holds `head <sha>` and `base <sha>` lines, `pre-fix.patch` the `git diff --binary` between them, so a kept run can rebuild the reviewed tree after it squashes onto `main`. `--plugin-dir <path>` passes `--plugin-dir` to every session so a run loads exo from that checkout. In task mode, a doc task that only adds one CHANGELOG.md line lands by script, with no session.
- **Detached runs**: every `exo run` (`skills/build/scripts/exo-cli.mjs`) takes the lock `.exo/run/lock` and writes `.exo/run/<id>/state.json` (pid, phase, log), only through `run-state.mjs`; a second run in the checkout refuses while the first lives, a lock whose pid is dead is taken over. `exo run` refuses a run root that is the checkout `exo-cli.mjs` runs from (`refuseLoadedCheckout`), so a run never edits the exo that drives it. `exo run <plan> --detach` spawns the run as a detached process logging to `.exo/run/<id>/run.log` and prints one line; on macOS the run process holds `caffeinate -i -w <pid>` from before run-plan until the land step ends, so the Mac stays awake, and a missing `caffeinate` is ignored; `exo status [<id>]` prints one line per run, and for a `stopped`, `crashed`, `parked` or `refused` run its phase reads `<phase>, waiting since <updatedAt>` there and in the first line of `exo wait`; `exo run --resume <id>` continues a run whose process died, with its stored plan and flags. The child sets `EXO_RUN=<id>` and `EXO_RUN_DIR` for run-plan; the final phase is `passed` (exit 0), `stopped` (1) or `refused` (2). With a `Land:` line, a passing run goes on to `land-run.mjs` (phase `landing`, stage `landing`) and ends `landed` (0) or `parked` (3); a run-plan exit 3 also ends `parked`, stage `build`. A parked run waits on the open lines of `.exo/run/<id>/gates.md` (`exo status` lists them); `exo approve <id>` approves them and continues like `--resume` by stage (build reruns run-plan, landing runs land-run only), while `--resume` refuses `parked` and `landed`. `exo run` writes `.exo/run/<id>/report.md` at start and at resume (phase `starting`) and at every final phase (a 15-line head, then every command the permission rules refused, read from `denied.txt`) and sends an `osascript` notification, ignored when `osascript` is missing. After the report, a `landed`, `passed` or `refused` run moves to `.exo/kept/<id>/`; `parked`, `stopped` and `crashed` runs stay in `.exo/run/<id>/`.

## Hooks

Rules for writing a hook live in `skills/edit-skills/references/hook-shape.md`.

`hooks/hooks.json` registers one hook process per event and matcher rather than one per feature: `hooks/session-start.mjs` on `SessionStart`, `hooks/dispatch-bash.mjs` on `PreToolUse` for `Bash`, `hooks/agent-effort.mjs` for `Agent` and `hooks/dispatch-edit.mjs` for `Edit`, `Write` and `MultiEdit`, and `hooks/context-limit.mjs` for the other matched tools (`Read`, `Glob`, `Grep`, the web tools, `Skill`, `NotebookEdit`, `ToolSearch`, `mcp__.*`). `hooks/subagent-start.mjs` runs on `SubagentStart` for every subagent and puts the context limits and the hand-over route (write the result file the brief names, Write still works past the hard limit) into the subagent's own start context, so the later hook note is not read as injected text. `hooks/run-no-wait.mjs` runs on `PreToolUse` for `AskUserQuestion` and on `Stop`, and acts only inside an exo run (`EXO_RUN_DIR` set): it denies a question and blocks an end without a status line, telling the session to decide from the spec and settings and log the choice in `<EXO_RUN_DIR>/decisions.md`. Blocks are counted per session in `blocks.json`; after 2 the end passes and `<EXO_RUN_DIR>/blocked` holds `Task <n>: BLOCKED <last line>`. The Bash dispatcher fixes two shell gaps through `lib/shell-fixes.mjs` by adding a prefix and leaving the command text as written: a command with an `=` word gets `setopt noequals` under zsh, and one holding `for <name> in $<NAME>` with the list unquoted also gets `shwordsplit` there, and a command naming `timeout` gets a `timeout()` shell function wrapping a perl alarm only when no `timeout` is on PATH, so the shell resolves every `timeout` itself; a command calling `sed` with a bare `-i` on BSD sed gets a `sed()` function that passes `-i ''` to `command sed`. It skips this in a run session (`EXO_RUN_SESSION=1`, set by `childEnv` in every run-plan child), whose prefix allow rules a prefixed command would no longer match; where run-plan installs the stall guard, `hooks/run-stall-guard.mjs` applies the same fix. The Bash dispatcher also denies, only when the call carries an `agent_id`, a `git` command matching `SHARED_STATE_GIT` in `lib/git-deny.mjs` (stash, worktree remove, prune and move, branch delete and rename), the list `run-session.mjs` builds its `DENY_RULES` entries from. The list stops a subagent's accidental direct git call on shared state and is not a sandbox: git code fed to a shell interpreter through stdin, a here-string or a pipe (`bash <<< "git stash"`, `echo "git stash" | sh`) is out of scope. It runs the context check, in process, and `agent-effort.mjs` runs it too, so those tools get no extra process. The context check denies only in subagents and detached run sessions; in the main session it adds a note once per level, at 60k and 80k, telling the lead to write its state to `.exo/<topic>/progress.md` first, then delegate the rest to subagents and never start a fresh session. The session text carries one `- Off-brief return →` line: an agent that loops, does unrequested work, weakens a test or returns the wrong shape gets one SendMessage naming the drift and the rule it broke, and is stopped or redispatched only when its next return still drifts or it is past its hard context limit; a new review finding keeps the `**Fix rounds.**` rule. Hook code (`hooks/**/*.mjs` plus `lib/hook-input.mjs`) stays within `HOOK_LINES_LOCK` in `verify/budgets.mjs`, checked by `verify/checks/hook-size.mjs`.

- **SessionStart** (startup, resume, clear, compaction): writes the plugin-root pointer to `~/.claude/exo/plugin-root` (under `CLAUDE_CONFIG_DIR` when set) only when `CLAUDE_PLUGIN_ROOT` resolves to the copy the hook runs from, so a hand run or a cloned copy leaves it alone. Beside it, `plugin-main` names that copy's main checkout, read from its `.git` file; the status line launcher, the `exo` shim and `exo-cli.mjs` use it once the pointed worktree is gone. On Claude Code the hook also upgrades an old status line launcher in place. It injects only this context: the handoff and memory pointers when those files exist, the handoff pointer quoting the prompt of its last `Resume:` line, on compaction, clear or resume a pointer to the newest `.exo/*/progress.md` modified within `EXO_PROGRESS_POINTER_MS` (default 1 hour), the settings line (no reply-length entry or rule text; short replies come from the `exo:adhd` output style), the Codex host note on Codex, and the routing and session rules from `hooks/session-routing.md` and `hooks/session-rules.md` when those files exist, in that order, then on Codex the dispatch rules from `hooks/dispatch-rules.md`. On Claude Code it clears the session's dispatch marker instead. The rest of the `route-skills` body, a welcome and the book sentence are not injected; `route-skills` stays a user-only skill and runs the rest only when called.
- **Delegation triggers** (`hooks/session-rules.md`): the session text keeps the main session inline by default and lets work leave it only when a trigger it can check before starting holds: T1 small task (inline), T2 web research or a long search whose output the lead need not keep (`fetch-docs` or `locate-code`), T3 2+ independent parts of 6+ tool turns each (one subagent per part, Agent calls in one message), T4 steps that each need the previous result (one worker, never split), T5 remaining work of 2+ tool turns at the 60k warning (subagents), T6 an agent expected to run over 5 minutes (`run_in_background`).
- **Dispatch rules** (`hooks/dispatch-rules.mjs`): the first `Agent` call of a main session, outside a detached run session, gets the text of `hooks/dispatch-rules.md` (the lead passes no `model` or `effort` for `exo:` agents, long command output goes to a log, `exo:fetch-docs` returns inline instead of writing a file, and an unnamed delegate's brief opens with `exo-kind: hardest` when it leaves a design, architecture or solution choice open or asks for an unknown cause, `exo-kind: build` for a fully decided fix) as `additionalContext` from `hooks/agent-effort.mjs`; a marker file `exo-dispatch-<session id>` in the temp folder keeps later calls free of it until the next SessionStart clears the marker. A subagent's call gets none, as it never got the session text.
- **Unnamed job words** (`filled` in `hooks/agent-effort.mjs`): an unnamed `Agent` call with no `exo-kind:` line takes its kind from `unnamed.jobs`; a description word counts when it is a job word or the job word plus `s`, `es`, `d`, `ed` or `ing` (a silent final `e` dropped before `ing`), case-insensitive, so `pickup`, `picker`, `designated`, `findings` and `fixtures` match nothing, and the first job word in table order wins over all description words, so `Fix edit-evidence false block cause` runs on `hardest` and `Fix the typo` on `build`; no match keeps `unnamed.kind` only where the deny below does not apply.
- **Unlabelled dispatch deny** (`agentHook` in `hooks/agent-effort.mjs`): under budget `on`, a `general-purpose` or `claude` `Agent` call with no model, no effort, no `exo-kind:` line and no job word in its description is denied; the reason tells the lead to add `exo-kind: <kind>`, naming `hardest` for an open choice or unknown cause. A labelled call, a call with a job word, an `exo:` agent and any call under `off` pass.
- **Edit-impact note** (`lib/edit-impact.mjs`, a step in `hooks/dispatch-edit.mjs`): the first `Edit`, `Write` or `MultiEdit` of an existing non-test source file per session adds one note naming at most 6 files that import it (at most 3 of them tests), found by one `git grep --no-index` on the file's import name. Seen files are remembered in `exo-impact-<session_id>` under the temp dir. The search stops after `EXO_EDIT_IMPACT_MS` (default 2000); a timeout, an empty result or a missing `session_id` adds nothing.
- **Context limits** (`lib/context-limits.mjs`): each matched tool call reads the context size from the tail of the caller's own transcript. The hard limit is the fixed `CONTEXT_LIMIT`, 80k, with no setting; the soft limit is 75% of it, `SOFT_RATIO`. `run-plan.mjs` reads the same constant for a run's context budget and no `contextLimit` setting. It acts on subagents and detached run sessions, and on the main session by note only, once per level, remembered in `exo-context-<session_id>` under the temp dir. Past the soft limit it adds a note to finish the step and hand off; past the hard limit it denies the tool, and the session ends with its report or handoff. Apart from those limits, a main-session `Read` of a whole persisted tool output (`<transcript>/tool-results/*.txt`, written when a result is too large to show inline) is denied, `persistedReadDecision`; a `Read` with `limit`, a grep or a subagent reads it instead.
- **Cap headroom** (`warnNearCap` in `skills/spec/scripts/plan-check.mjs`): in a root holding `verify/budgets.mjs`, plan-check adds `warning: Task N edits <file>` for each unlanded task whose `Files:` lists a skill or agent with fewer than `defaults.capHeadroomTokens` (50, `lib/run-providers.json`, override in `~/.config/exo/run.json`) tokens of body headroom left, unless that task or an earlier one lists a `references/` file of the same skill. It measures with the root's own `verify/body-size.mjs`, run in a child process that `EXO_BODY_SIZE_TIMEOUT_MS` (default 60000) stops; a timeout skips the check with a warning. A warning does not fail the check.
- **Tbench watcher** (`benchmarks/tbench/watch.mjs`): `defaults.tbench` in `lib/run-providers.json` (override in `~/.config/exo/run.json`) holds `limitUsd`, the spend at which it stops Harbor, and `trialUsd`, the charge for a running trial in a job with no finished trial; otherwise a running trial is charged that job's highest finished cost. `EXO_TBENCH_POLL_MS` sets the poll interval (30000). Run one watcher per Harbor job; its SIGTERM also ends the running trials.
- **Provider models** (`providers.deepseek` and `providers.zai`, `lib/run-providers.json`): `deepseek` maps every tier, `ANTHROPIC_MODEL` and the subagent to `deepseek-flash`, with efforts `low`, `high`, `max` and no provider `effort`; `zai` maps Haiku to `glm-5.3-flash` and the rest to `glm-5.3`. `resolveProvider` adds `EXO_PROVIDER=<name>` to the session env. With no provider `effort` in the entry, each dispatch follows its `deepseek` kind column and only an explicit `--effort` sets `CLAUDE_CODE_EFFORT_LEVEL`, because that variable outranks a dispatch's effort. Each provider's column in `lib/model-kinds.json` picks a subagent's effort: `hooks/agent-effort.mjs` takes the session's `EXO_PROVIDER` column when the table lists it, else the `claude` column; `providers.deepseek` maps every tier to `inherit`, maps `low` to `low`, `medium` and `high` to `high`, and `xhigh` and `max` to `max`, and its `kindEfforts` puts the `on` column of `build-task`, `doc-task`, `coordinate` and `run-unit` at `low` while their `retry` column keeps `high`; `budgetPin` in `run-plan.mjs` pins an `exo run` task session to a listed provider's `effort` with no model. Neither block sets a `[1m]` suffix or `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, so Claude Code compacts at its default window; widen it per provider in `env` in `~/.config/exo/run.json`.
- **Provider keys and sessions** (`skills/build/scripts/exo-cli.mjs`): `exo key set <provider>` stores the provider's key in `~/.config/exo/keys.env` through `writeKey` in `run-keys.mjs`; it reads the key without echo on a terminal or one line from stdin when piped, never prints it, and refuses a provider with no `key` in the run config. `exo claude [--provider <name>] [--effort <level>] [-- <claude args>]` (`exo-claude.mjs`) starts an interactive Claude Code session with the provider's environment from `resolveProvider`, drops an inherited `ANTHROPIC_API_KEY` for a non-`claude` provider, refuses a missing key with the line `exo key set <name>`, and refuses inside a Claude Code session.
- **Measured goal** (`skills/spec/references/measured-goal.md`): the spec reference for a Goal that is a score, cost or time on a task set; it calibrates with `benchmarks/tbench/readouts.mjs --calibrate`, sizes with `benchmarks/mde.mjs` and compares arms paired; its References row raises `STAGE_BODY_TOKENS.spec` in `verify/budgets.mjs` from 760 to 783.
- **Delegate limits**: each agent that builds, reviews or repairs sets `maxTurns` in its frontmatter (60; `run-unit` 90, `fix-review` 40); the harness ends a delegate at that turn.

Each hook entry pins `"shell": "bash"`, else a Windows host without Git Bash falls back to PowerShell; the hook command stays in shell form, not `args`, so Claude Code resolves the shell, not `bash` on `PATH`. The session hook stays Node (`hooks/session-start.mjs`), with no `jq`. `.gitattributes` forces LF, because a CRLF shebang fails silently on Windows.

The plugin ships no permission guard: a cap on what a machine may do belongs in that machine's own configuration.

## Codex

`lib/model-kinds.json` stays the one table: `provider` stays `claude`, and its `providers.codex` block maps each tier to a Codex model and effort. `harnesses/codex/generate.mjs` applies `harnesses/codex/rules.mjs` to the Claude sources and builds the Codex tree in memory: each skill rewritten with its `agents/openai.yaml`, and `agents/exo-<agent>.toml` per agent. The Codex installer builds it fresh on every install, so the tree is never committed; `npm run generate` writes it to the gitignored `harnesses/codex/generated/` for inspection only, and nothing reads that copy. `npm run check` fails when the sources cannot generate the tree.

`harnesses/codex/overrides/<path under generated>` replaces one generated file and opens with `<!-- exo:override source-sha256=<hash> -->`. Add one only after a skill reads wrong in a real Codex run; a changed source hash fails `npm run check`.

`install.mjs` runs one adapter per harness, listed in `harnesses/registry.mjs`. An adapter is `harnesses/<name>/adapter.mjs` exporting `name`, `label`, `detect(env)`, `install(plan)`, `update(record)`, `remove(record)` and `recorded(env)`; a new harness is one adapter folder plus one registry line. The Claude adapter runs `claude plugin install exo@blauwtje -s <scope>`; the Codex adapter copies the generated skills and agents and merges the allowlisted hook entries from `harnesses/codex/hooks.mjs`. Each records its installs in `installed.json` under its config home.

Codex hooks and generated script commands run through `harnesses/codex/hook-entry.mjs` and `harnesses/codex/run.mjs`, which set `EXO_HOST=codex`; `lib/host.mjs` treats a missing or unknown value as Claude Code. Try an install against a scratch folder with `HOME=<dir> CODEX_HOME=<dir>/.codex node install.mjs --harness codex --yes`.

## Releasing

A release is cut weekly, not per merge: a scheduled run every Monday 06:00 UTC cuts it when `## Unreleased` holds an entry, and `gh workflow run release.yml` (or the Run workflow button on the Actions page, optionally with `-f level=patch|minor|major`) cuts one sooner. A scheduled run uses level `auto`, which reads the level off `## Unreleased`. `.github/workflows/release.yml` runs only on `main`. It checks with `npm run release-pending` whether `## Unreleased` holds an entry; if so it runs `npm run check` and `npm run bump`, commits `chore(release): <version>`, tags `v<version>`, pushes both and publishes the GitHub Release from `npm run release-notes`. With nothing under `## Unreleased` it cuts no release.

A change lands on `main` as one squashed commit carrying its changelog entry, and `### Highlights` when deserved, but never a version; entries collect under `## Unreleased` until the next release. The release push uses `GITHUB_TOKEN`, which starts no further workflow, so the release commit does not release itself. After a release, `claude plugin marketplace update blauwtje` and `claude plugin update exo@blauwtje` install it locally; the marketplace compares only the manifest version, so an unbumped release installs as a no-op.
