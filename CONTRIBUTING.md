# Contributing

## Set up

Clone the repository and run `npm install` once. You need Node 22 or newer and `bash` on `PATH`; the verifier and tests use only the Node standard library.

A marketplace added from `blauwtje/exo` on GitHub installs a cache copy, so an edit there is live only after a release; `claude --plugin-dir <your clone>` runs the working tree instead. A marketplace added from a local directory whose `marketplace.json` sets `"source": "./"` (this checkout is one) loads the plugin in place, with no cache copy: an edit is live after `/reload-plugins`.

## Checks

### Gate

| Command | What it runs |
|---|---|
| `npm run check` | The gate before any commit: `node verify.mjs`, the verifier with the script tests. `verify.mjs` starts the script tests first and runs the other checks while they run, then reports the test result in its usual place. |
| `npm run validate` | `npm run validate:static` and then `npm test`: the structural checks, then the script tests. |
| `npm run validate:static` | The structural checks only, no script tests. |
| `npm run check`, `npm run validate:static` | The `edit evidence` check fails a branch whose commits since the merge base with `origin/main` change `skills/*/SKILL.md`, `skills/*/references/*.md`, `agents/*.md`, `hooks/session-routing.md`, `hooks/session-rules.md`, `hooks/dispatch-rules.md` or `harnesses/codex/host-note.md` without an `Evidence:` trailer on any commit: `none (<reason>)`. On any range it also fails an `Evidence:` line that is malformed, even with no wording change. It is `UNRUN` without a merge base. |
| `npm run check`, `npm run validate:static` | The `test timing` check fails a `tests/*.mjs` assert that compares one raw elapsed value (`Date.now() - start`, `performance.now() - start`, `process.hrtime.bigint() - start`, or a variable set from one) to a number literal, because a loaded machine breaks the bound. Compare two timed runs instead, or start the assert message with `timing-ok:` and a reason. It reads one line per assert. |
| `npm run check`, `npm run validate:static` | The `covering tests` check fails when `coveringTests` in `lib/covering-tests.mjs` no longer maps `skills/build/SKILL.md` to `tests/agents.test.mjs`, the pair `land-task` relies on to run the tests that read a changed file. |
| `npm run check`, `npm run validate:static` | The `boundary rows` check fails when a `Boundary:` line in `docs/specs/*.md` names a test file on disk that holds no test whose title contains `out-of-scope`. A named file not on disk is skipped. |
| `npm run check`, `npm run validate:static` | The `budget raises` check fails each numeric value in `verify/budgets.mjs` raised since the merge base with `main` unless a commit in that range has the body line `Budget-raise: <export>.<key> <old> to <new>: <reason>`; trim the text instead. |
| `npm run check`, `npm run validate:static` | The `module surface` check fails an export in `lib/` or `hooks/` that no tracked file imports, and one function body defined in two modules of `lib/`, `hooks/`, `verify/`, `harnesses/` or `skills/*/scripts/`. |
| `npm run check` | The `refusal fixtures` check runs each call in `tests/fixtures/hook-refusal-calls.json` through its hook script and fails when a call gets a verdict other than its `pass`, `note` or `deny`, so a legitimate call that is refused or a harm call that passes shows before a commit. |
| `npm run check`, `npm run validate:static` | The `agent duplicates` check fails a rule line repeated, after normalising, within one load chain (a `SKILL.md` with its references, an agent file with `lib/references`, the hook texts); `verify/agent-shared-lines.txt` lists the tolerated repeats and a stale row fails. |
| `npm run check`, `npm run validate:static` | The `body budgets` check holds loaded prose (`.md` under `skills`, `agents`, `hooks`, `lib/references`, `lib/agent-modes`, `output-styles`) at or under `LOADED_PROSE_LOCK` in `verify/budgets.mjs`; instruction density has no allowlist. |

CI runs `npm run check` on Node 24 on Ubuntu for every push to `main` and every pull request.

`npm test` prints Node's spec reporter, which marks a failure with `✖`. `npm run check` runs the same tests through TAP, so its failure line names each failing test as `not ok`. Both load `tests/clean-run-env.mjs` first, which strips the run variables `EXO_RUN`, `EXO_RUN_DIR`, `EXO_RUN_TASK`, `EXO_RUN_SESSION`, `EXO_DROPS` and `EXO_PENDING_EVIDENCE`, so a test inside `exo run` leaves the live run without parked gates. It also drops every `CLAUDE_PLUGIN_OPTION_*` variable and points `CLAUDE_PROJECT_DIR` at an empty folder, so no test reads the developer's exo settings.

The `instruction density` check fails a list item of three or more sentences and a sentence over 40 words in the Markdown under `skills/`, `agents/` and `output-styles/`, outside fenced code, frontmatter, HTML comments, headings and tables; an inline code span counts as one word. There is no instruction-density allowlist.

The `prose style` check fails an instruction file with over 30% arrow bullets, a bullet holding two semicolons, more than two `never`, or, in a `SKILL.md` or agent file, no goal line; it covers `skills/`, `agents/`, `hooks/`, `output-styles/`, `harnesses/codex/host-note.md`, `.claude/CLAUDE.md`, `README.md` and this file.

The `boundary words` check compares each `.md` file under `skills/`, `agents/`, `rules/` and `hooks/` that exists at the merge base with `origin/main` and in the working tree, counting `only`, `not`, `no`, `never`, `every`, `each`, `all`, `full`, `except` and `unless` as whole words, and fails when a count falls; it is `UNRUN` without `origin/main` or a merge base with it. A deliberate drop is named as `Drops: <word> in <path>[, <word> in <path>]`, in a plan task's field line (land-task passes it to the land gate as `EXO_DROPS` and copies it into a compact task's commit body) or in a commit body since `origin/main`.

The `git whitespace` check runs `git diff --check` from the merge base with `origin/main` to the working tree, so committed, staged and unstaged changes are all covered; without a merge base it checks the working tree only. It also scans untracked files for trailing whitespace.

The `derivation` check fails when a name exo does not own reaches a shipped file, or a third-party notice file appears at the repository root. `LICENSE` is the whole licence. The names sit base64-encoded in `verify/checks/derivation.mjs`, because a plaintext list would be the text the check forbids. `plan-check.mjs` scans a brief that targets this repository for the same names and names each with its line, so a plan is reworded before its first land gate.

The `fix-class load` check fails once per repair text that does not name `fix-class.md`: `skills/build/review-fixer-prompt.md`, the `## Shared block` of `skills/find-cause/fixer-prompt.md` and `agents/build-task.md`. A new repair agent text joins `REPAIR_TEXTS` in `verify/checks/fix-class-load.mjs`.

The `script help` check fails a `skills/*/scripts/*.mjs` entry point, a file with a shebang or an `isMain` call, that has neither a `--help` comparison (`===`, `includes`, `case`) nor a `parseFlags` call passed `usage`. It reads source and runs no script.

## Editing a skill

Load the `edit-skills` skill before any skill or delegate-prompt edit; it holds the shape and size rules the verifier enforces. `verify/budgets.mjs` names the skills the full verifier checks; every other skill still passes the frontmatter, portable-language, description-budget, body-budget and reference-shape checks. Add a skill there once it reaches that shape.

A skill whose work leaves the machine (a push, pull request, merge or issue) runs only on the authorization its body names: the user's pick of a finish route or a plain request. The one exception is `ship` under `ship=ask`, which pushes a non-default branch to origin without asking; merge, default-branch push, pull request and issue still ask. It leaves every branch in place and cuts no release.

Four skills carry `disable-model-invocation: true`, because only the user should start them, and user-only also removes a skill's description from the fixed context: `configure` changes settings, which the user should ask for by name; `prompt` runs a rewritten prompt after the user's approval; the `research` and `ideate` modes of `spec` run a paid multi-agent search and idea loop. Every other skill stays model-invocable; `save-session`, `write-docs` and `edit-skills` open their description with `Use when the user asks`, so the model starts them only on the user's words, and the rest open with `Use when` so a next-stage answer can start them. `verify/checks/skill-frontmatter.mjs` fails model-facing text in `skills/`, `agents/`, `hooks/` or `lib/` that names a user-only skill as bare `exo:<name>`; `/exo:<name>` stays allowed as text for the user to type.

`ABOUT.md` says what exo is and lists exo's domain words with the synonym each replaces. Skill bodies, replies and commits use the left column; the `derivation` check reads the file for names exo does not own.

A new skill needs all of: the folder `skills/<name>/`, its name in `EXPECTED_SKILLS` in `verify/budgets.mjs`, its reference rows in `verify/reference-owner-rows.txt`, room for its description in `DESCRIPTION_TOTAL_LOCK` and `DESCRIPTION_TOTAL_WARN`, and a page under `docs/skills/`. Write a skill from a discipline you have read, not from a one-line description.

Grade a pressure case with `node skills/edit-skills/scripts/pressure.mjs --grade`: it scores each run pass or fail against the tagged lines of the case's `criteria.md`, applies `--threshold` over the runs (1 run and 1 judge vote by default, 3 each under `--full`) and reports the with-minus-without delta; `--contrast-style <a>,<b>` compares two output styles and prints `WRONG STYLE` when a run's init event reports another. It runs outside `npm run check` and `npm test`.

Rename a skill with `node skills/edit-skills/scripts/rename-skill.mjs --from <old> --to <new>`. It moves the skill folder, its `docs/skills/` page and its pressure folder, then rewrites every word-bounded mention outside `CHANGELOG.md`.

A `SKILL.md` body after its frontmatter stays within `SKILL_BODY_TOKENS.ceiling` in `verify/budgets.mjs`, counted as bytes / `BYTES_PER_TOKEN`, because a body is paid for on every run; bulk lives in `references/` and the body names the step that opens it. A reference longer than `REFERENCE_CONTENTS_LINES` opens with a contents list linking each `##` section, and no reference links to another. `PENDING_TRIM` lists the skills not yet trimmed to these. Split a skill in two only when the halves fire at different moments, because each skill adds its trigger to every session's listing.

## Adding a setting

A new setting is one entry in `skills/configure/schema.json` plus the matching `userConfig` entry in `.claude-plugin/plugin.json`.

`.gitignore` un-ignores `docs/principles/`, `docs/skills/`, `docs/behaviour/`, `docs/codex.md` and `docs/settings.md`, and `docs/specs/` is tracked too.

`docs/principles/README.md` indexes Anthropic's engineering principles; the `principles` check fails a page that is undated, unsourced, unmapped or over budget, fails a backticked path cite after `exo:` unless it names an existing file or folder exactly, so any `:` or `#` tail fails, and an anchor span after one space (at least 2 identifier characters, text that must occur in the file; a folder cite takes none) that is gone, and warns when its `Checked:` date is older than `EXO_PRINCIPLES_STALE_MS` (90 days). The index states the value rule: a hook, check, agent, review, model tier or retry stays only when its value is at least its cost in tokens, time and false blocks.

## Evals

`claude plugin eval` runs the suite under `evals/` (a case is `evals/<case>/case.yaml` with its graders inline, or `prompt.md` with `graders/`; a scaffolded case adds a one-line `scaffold.sh` that calls `evals/scaffold.sh`); `evals/results/` is gitignored. Run it only before a release: `EXO_ROOT="$PWD" claude plugin eval --scaffold --allow-tools Bash Edit Write --json --max-cost-usd 20`.

`docs/scorecard.md` lists the commands for each column and holds one table. Each release appends one row and no row is rewritten. `docs/failures.md` lists the failures seen in real sessions.

## How a skill dispatches work

- Nine roles are plugin agents under `agents/`, because an agent file fixes a tool list and a turn limit, and its body is the system prompt rather than text pasted into every dispatch. A role becomes an agent only when one effort, one tool list and one turn limit fit every dispatch. Each agent's description says what it does. `agents/orchestrator.md` is the general orchestrator, added after a `general-purpose` orchestrator was refused twice by `hooks/agent-effort.mjs` for worker briefs with no `exo-kind:`, was refused a report file Write, and hit the 60k context note while waiting on workers. It runs on the `orchestrator` kind, Opus at `medium`, lowered from `high`.
- `exo:review-branch` runs on the `review-deep` kind's model and effort, through the `exo-kind: review-deep` label its table entry lists, when a landed task's `Risk:` field names a security boundary; any other `Risk:` field gets the light reviewer. On scope `branch` it reads `.exo/review-input.md`, which `verify.mjs --reviews-only` writes each round with each landed task's `Red:` lines (the reviewer reads no implementer report), before the plan and the diff. It fixes nothing. On `FINDINGS`, `verify` hands its report to `exo:build-task` with an `exo-kind: fix-review` prompt line, then runs the Final verification once. The round-2 rule for `fix` and `report` lines and the `Red:` source rule live in `skills/gate/references/review-rules.md`, and the `reference tables` check keeps them there.
- `lib/model-kinds.json` owns every model and effort: it maps each agent file to a task kind and each kind to a tier and an effort, so this page names neither. `lib/model-kinds.mjs` validates it, `hooks/agent-effort.mjs` applies it to a dispatch, and `skills/build/scripts/run-plan.mjs` and `run-tail.mjs` pick the kinds a headless run uses. An `exo-kind:` label moves an `exo:` agent off its own kind only when the call also passes `model` or `effort`, or the agent's entry lists that label under `labels`.
- The `budget` setting turns the per-kind table on or off. Under `on`, `agent-effort` sets each dispatch's model and effort from the kind's `on` cell and denies an `exo:` call whose passed pair differs; under `off` every agent inherits the session. A refused `land-task` ends with `exo-retry`, which gives the dispatch the kind's `retry` cell (`lib/refusal-handlers.mjs` holds each `Then:` line, `land-task.mjs` the refusals that skip it). `lib/settings-store.mjs` holds the `budget` schema and its old-name aliases.
- The `claude` provider maps the `deep` tier to `inherit`, so `hardest` and `review-deep` run on the main session's model with the kind's effort.
- `next-task.mjs` prints the `input unreachable` handler, not the `plan drift` handler, when a drift item is an input path this machine cannot read, because no repair session can supply it; the run stops `BLOCKED` with that path. `lib/refusal-handlers.mjs` holds the handler and `skills/build/references/run-loop-direct.md` the routing.
- `unnamed.jobs` in `lib/model-kinds.json` maps a job word to a kind for an unnamed dispatch; the **Unnamed job words** bullet under Hooks states how a description word matches.
- `lib/check-citations.mjs` takes a JSON list of url and quote pairs and prints `verified`, `missing` or `unreachable` for each; `research-worker` runs it on a web result before returning. It reads the saved page for a cited URL from `sources.jsonl` and `pages/<ref>.txt` or `t-<id>.txt` beside the cites file, and fetches only when none is saved.
- `lib/map.mjs` `mapItems({ items, run, capUsd })` runs a bulk item list through `run` one by one and stops once the summed `costUsd` reaches `capUsd`, returning the results, the spend and the items left.
- Every other delegate is the harness's `general-purpose` agent; the dispatching skill passes its model and effort from `lib/model-kinds.json` through a `dispatches` entry and hands it the role text from a `<role>-prompt.md` beside the skill.
- `skills/build/references/worker-round.md` dispatches each round worker as a `general-purpose` delegate on the `improve-round` kind (`strong`, `high`), with `skills/build/references/worker.md` as the template of the per-run brief `setup.mjs` and `round.mjs` write to `.exo/improve/<tag>.brief.md`; the delegate's prompt only points at that brief. The worker runs `skills/build/scripts/fast-check.mjs` once per candidate, which runs the fast check and the tests covering the touched files, and returns `IDEA <hash>`.
- An agent that takes everything from its dispatch sets `omitClaudeMd: true` (Claude Code 2.1.271 or later) and carries the rule against deleting past a blocked state in its own body, because it loads no `CLAUDE.md`.
- `CLAUDE_CODE_SUBAGENT_MODEL` outranks the named model on Claude Code before 2.1.251.
- The session's effort reaches no subagent: the `agent-effort` hook sets effort at dispatch, and every `dispatches` entry passes a model and an effort in the call. `CLAUDE_CODE_EFFORT_LEVEL` overrides them, so only `exo claude` sets it, for an explicit `--effort` or a provider entry that names an `effort`.
- The stage skills pin no model: a pinned model would override the session's model and rebuild the prompt cache mid-session. Set `model` or `effort` in a skill only where its work always needs that tier.
- A delegate misses the session hook, and the session text carries no pointer to `lean.md`, so the four delegate prompts and agents that write code read `lib/references/lean.md`, or carry lines from it: `agents/build-task.md`, `skills/build/bug-fixer-prompt.md`, `skills/build/review-fixer-prompt.md`, and `skills/find-cause/fixer-prompt.md`. `agents/build-task.md` also reads `lib/references/code-standard.md` in its `## Return` step and fixes its own diff against it before `land-task.mjs --check`. It holds the push-back, anti-bloat and trivial-task lines from the Karpathy post of 2026-01-26.

## Verifying in one round

A plan whose tasks all landed passes `exo:gate` in one round, because land catches what the gate caught late and a repair is committed and rechecked inside the round.

- **Tests at land**: after the Land gate passes, `land-task.mjs` runs the tests that read the task's changed files and refuses the land, naming the test, when one fails. `lib/covering-tests.mjs` finds them by scanning `tests/*.test.mjs` for a quoted path equal to a changed file or one of its ancestor folders, also with a leading `${...}` removed or a leading `./` or `../` resolved against `tests/`; the `covering tests` check fails when a known pair, such as `skills/build/SKILL.md` and `tests/agents.test.mjs`, stops matching.
- **Shards**: `gate.mjs` splits the branch diff into shards that each fit one reviewer's context budget and together cover every changed file; a file over budget is split by hunk ranges. Each shard gets its own `DISPATCH Branch <i>/<n>` line and review-input file.
- **Coverage**: `agents/review-branch.md` ends its file with `Read: <paths>`. `merge-reviews.mjs` unions the `Read:` lines of every report but `review-overlap`, so a rerun report under any other name counts, prints `COVERAGE <read>/<total>`, prints `UNREAD-FILE <path>` for each changed file nobody read, and caps the verdict at FINDINGS while one is unread. Each `fix` finding carries a `Quote:` line of `agents/review-branch.md`; `merge-reviews.mjs` prints `DEMOTED-QUOTE <location>` and demotes the finding to `report` when that line is not in its file, so no fix-review runs for it (`DEMOTED-SETTLED <location>` names a fix finding whose rule and path `run-probes.mjs` already logged as `declined`. `DEMOTED-PREPASS <location>` is printed by `run-probes.mjs` for a fixed finding whose `Before:` line says its Probe already passed before the fix, and logs it `declined` without a rerun. The `DEMOTED` count covers fix findings without `Probe:`, `Class:` and `Sweep:` lines).
- **Boundary scope**: a task with `Risk: security boundary` carries `Boundary: in <inputs> | out <classes> | test <file>`, with `<file>` in its `Files:`, and plan-check refuses it without. `verify.mjs` copies each `Boundary:` line into the review input; a bypass in an `out` class gets weight `out-of-scope`, which `merge-reviews.mjs` does not count. The `boundary rows` check fails when a named test file holds no test titled `out-of-scope`.
- **Branch's own scripts**: when the verified repository is the loaded plugin's own source and the branch changed files under `skills/gate/`, `skills/build/review-fixer-prompt.md` or `lib/references/code-standard.md`, `verify.mjs` re-executes the branch's copy of itself. Changed `agents/` files print one `SELF-HOSTED agents=<paths>` line, because agents resolve by name from the loaded plugin.
- **Repair mode**: the fixer commits each repair after its proof, and `gate.mjs --repair` refuses a dirty tree (`FAIL fixer-uncommitted`), a fix count above 0 with no new commit (`FAIL fixer-no-commits`) and a findings file whose hash changed since review (`FAIL stale-findings`). It rechecks only the repair diff: the Land gate, the tests covering the changed files and each named guard, then one fix-diff review. `npm run check` runs once at loop exit. It prints a `LOOP next=fix|done|stop round=<n>/2` line that `skills/gate/references/repair.md` follows.
- **repair-bound**: at most two repair passes per round, counted in `<root>/.exo/verify-state.json`; a third prints `STOP repair-bound` and hands the open findings to the user.
- **Fix class**: every repair fixes the class of its finding, not the one line. `skills/build/references/fix-class.md` says to name the rule the code broke, fix the hits the finding names and add the cheapest guard that fails on a new instance, at most one per cause. Each repair commit body carries `Guard: <file> | none (<reason>)`; `--repair` fails a commit missing it (`FAIL fixer-no-guard`), more than one named guard (`FAIL fixer-many-guards`) and a guard outside the repair diff (`FAIL fixer-guard-not-in-diff`). The `fix-class load` check is the guard for the rule itself: it fails when a repair agent text stops naming `fix-class.md`.

## Unattended runs

`node skills/build/scripts/run-plan.mjs <plan.md>` lands a plan with no session open. It and `exo run` start only from a terminal: with `CLAUDECODE` set, as in a Claude Code Bash call, they refuse (`SESSION_REFUSAL` in `run-session-env.mjs`, exit 2), except `run-plan.mjs --dry-run`; a session builds the plan through `build` with subagents. Each unlanded task runs in a fresh `claude -p` process given `/exo:build <plan> --task <n>`, then one `/exo:gate` process and `verify.mjs` run. `--dry-run` runs the preflight and prints the task order, rules and first prompt without spawning; the script's header comment lists the other flags; `--max-iterations` defaults to twice the unlanded tasks, `--timeout` to 60 minutes per process (`EXO_REVIEW_TIMEOUT_MS` sets a tail review session's limit), `--model` and `--effort` to `agents/build-task.md`.

- **Refusal**: `run-plan: refused: <why>`, exit 2, when the checkout is off the plan's `Branch:`, on the default branch, has a tracked change, or `plan-check --loop` fails, or when `ensureServices` in `lib/services.mjs` finds a service the Proofs need down: a Docker row (compose file or Testcontainers dependency) starts OrbStack or Docker, whichever is installed, and waits `EXO_DOCKER_READY_MS` (default 60 s) for `docker info`, and `node lib/services.mjs --root <dir>` prints the same result.
- **Permissions**: every process runs under `--permission-mode dontAsk`, allowed only `Read`, `Edit` and `Write` in the checkout, the runner's scripts, the plan's `Proof:`, `Run:`, `Land gate:`, `Lint:` and `Allow:` commands, and read-only git, and denied `git push`, `gh`, history rewrites, `git commit`, `git stash`, `git clean`, `git restore`, `settings.mjs` and `memory.mjs`, so `land-task.mjs` is the only committer. Task and plan sessions also deny `Edit` and `Write` of the plan file (`denyRules` in `run-session-rules.mjs`); repair sessions keep plan `Edit`. `EXO_RUN_TASK=<plan-id>/<n>` makes `land-task.mjs` refuse any other plan, task or `--fix`. Only `--check` and `--code-rules` may name another task of the pinned plan, and they write no file.
- **Breach check**: after each process HEAD holds no new commit, or one whose parent is the old HEAD and whose only `Plan-task` trailer names the task; no branch ref may move, and no `refs/remotes/*` ref may move unless another session caused it: the run branch's remote-tracking ref must not move, appear or vanish, and no other one may move to a tip holding a commit the run made.
- **Output**: stdout gets one `[mm:ss]` line per event (run start, task start, idle after a sleep gap, landed, plan session done with its one `plan session: <k> tasks landed` line of time, turns, tokens and cost, failed or blocked, run done), then a summary of at most six plain lines ending on `Details: <dir>/summary.txt`; per-task lines, denials, verify lines, reports and manual checks go to `summary.txt`.
- **Stop**: the last line of `summary.txt` is one `run-plan: stop: ` line (`done, <k>/<k> tasks landed, gate PASS|FAIL`, `iteration cap`, `attempt cap <n> reached` (the `attempt` kind in `lib/loop-kinds.json` reaches its cap, see Loop budget), `no progress on task <n> in <k> iterations` (a failed attempt repeats an earlier one of that task: same last failing line and same changed paths), `task <n> blocked`, `breach in iteration <i>`, `exo not loaded` or `stopped by <signal>` (SIGTERM, SIGINT or SIGHUP, where the signal listener writes the stop records itself, adds `; land-task: <failing line>` from the current task's newest land-task output, and exits 1 unless a session is live, where the session's own listener ends the claude group and exits)). Only `done, <k>/<k> tasks landed, gate PASS` exits 0, a `parked: ` stop (a rebase conflict at review start included: the run aborts the rebase, opens land-run's gate and exits before any review session) exits 3, every other stop exits 1. A command outside the allowlist is denied and counted on stdout and listed in `summary.txt` (each cut to 120 characters), not a stop. The task is judged only by whether it landed, so a run of denials that lands nothing counts toward `no progress`. An interactive command stops the run at the timeout.
- **Logs**: `.exo/run-plan/<plan-id>/<UTC time>/`, one `iter-<k>-task-<n>.log` per process, one `land-task-<n>.log` per task holding every land attempt, plus `tail.log` and `summary.txt`.
- **Sessions and budget**: each session gets a prompt generated from `skills/build/run-task-prompt.md` (a `## Build session` or `## Plan session` section) and loads no skill; a build session runs the plan's `Land gate:` command before it reports the task done, and skips that step when the gate is `none`. `land-task.mjs` runs the gate on a candidate commit that carries `Plan-candidate: <plan-id>/<n>` in place of the `Plan-task:` trailer, so the gate sees the task's own diff, new files and `Evidence:` and `Drops:` trailers. Every `land-task.mjs` run (landing, `--check`, `--fix`) first takes the exclusive lock `exo-land.lock` in the checkout's git directory (a dead owner's lock is taken over, `EXO_LAND_LOCK_MS` caps the wait), so a `--check` and a landing take turns. A pass promotes the candidate to a new commit with the `Plan-task:` trailer on the same parent, a failure or crash drops it, and `--check` always drops it, each by `git update-ref` against the candidate's own sha, so a HEAD that moved during the gate refuses with `HEAD moved` and no landed commit is rewritten. A landing then asserts HEAD sits on the commit it started from and holds only `Files:` paths. A passing `--check` writes `.exo/checked-<n>`. While the gate runs, `EXO_PENDING_EVIDENCE` holds the `Evidence:` values of the plan's other unlanded tasks, which satisfy the `edit evidence` check's need for one trailer. Proofs and verify run without it. a test that writes outside the run folder fails with EPERM in the sandbox, the session does not rerun it, and land-task's Proof runs it outside the sandbox. `--session auto|task|plan` picks the shape: `plan` builds all unlanded tasks in one session, `auto` (default) picks it for at most four tasks with disjoint `Files:` and no design task, else `task`. `--session plan` refuses when two tasks list the same path. A plan session runs `land-task.mjs --check --task <n>` with the plan report as `--report` before each task's GREEN line, fixes a Lint, Land-gate or code-rule refusal and reruns it, and ends `PLAN DRIFT` on a refusal it cannot fix or the same refusal twice. The Success run, then the review and fix rounds after the build, run by script from `run-tail.mjs`: the Success criterion runs first on the head tree (one `fix` session repairs a red result, a second red result stops the run), and no review starts before it passes. Each CLEAN or FINDINGS review verdict is stored with its tree in the check cache, and a resumed run skips the review of an unchanged tree and reuses its report and verdict. The `review done: <name>: <verdict> (<model>, <n> findings)` line in `run.log` names the session's model (`unpinned` when none) and, with a verdict line, its finding count. Each session appends one line to `sessions.jsonl` in the log folder, ending in the session's `model` (the reported one, else the pinned one). `--max-run-usd` (else run.json `defaults.maxRunUsd`) caps the sum of their `costUsd`: one `budget:` line at 80% of the cap, then the run stops after the task that reaches it with exit 4 and a `budget:` stop line, and `receipt` lines show the cost per task and per session kind, with a session that reported no cost shown as unknown (`--max-budget-usd` caps one session). Before the review fix session starts, `run-tail.mjs` saves the commit the review saw in the log folder: `pre-fix-head` holds `head <sha>` and `base <sha>` lines, `pre-fix.patch` the `git diff --binary` between them, so a kept run can rebuild the reviewed tree after it squashes onto `main`. `--plugin-dir <path>` passes `--plugin-dir` to every session so a run loads exo from that checkout. In task mode, a doc task that only adds one CHANGELOG.md line lands by script, with no session.
- **Detached runs**: every `exo run` (`skills/build/scripts/exo-cli.mjs`) takes the lock `.exo/run/lock` and writes `.exo/run/<id>/state.json` (pid, phase, log), only through `run-state.mjs`; a second run in the checkout refuses while the first lives, a lock whose pid is dead is taken over. `exo run` refuses a run root that is the checkout `exo-cli.mjs` runs from (`refuseLoadedCheckout` in `run-checkout.mjs`), so a run leaves the exo that drives it unedited. `exo run <plan> --detach` spawns the run as a detached process logging to `.exo/run/<id>/run.log` and prints one line. On macOS the run process holds `caffeinate -i -w <pid>` from before run-plan until the land step ends, so the Mac stays awake, and a missing `caffeinate` is ignored. `exo status [<id>]` prints one line per run, and for a `stopped`, `crashed`, `parked` or `refused` run its phase reads `<phase>, waiting since <updatedAt>` there and in the first line of `exo wait`. `exo run --resume <id>` continues a run whose process died, with its stored plan and flags. The child sets `EXO_RUN=<id>` and `EXO_RUN_DIR` for run-plan. The final phase is `passed` (exit 0), `stopped` (1) or `refused` (2). With a `Land:` line, a passing run goes on to `land-run.mjs` (phase `landing`, stage `landing`) and ends `landed` (0) or `parked` (3). A run-plan exit 3 also ends `parked`, stage `build`. A parked run waits on the open lines of `.exo/run/<id>/gates.md` (`exo status` lists them). `exo approve <id>` approves them and continues like `--resume` by stage (build reruns run-plan, landing runs land-run only), while `--resume` refuses `parked` and `landed`. `exo run` writes `.exo/run/<id>/report.md` at start and at resume (phase `starting`) and at every final phase (a 15-line head, then every command the permission rules refused, read from `denied.txt`) and sends an `osascript` notification, ignored when `osascript` is missing. After the report, a `landed`, `passed` or `refused` run moves to `.exo/kept/<id>/`. `parked`, `stopped` and `crashed` runs stay in `.exo/run/<id>/`. `exo undo <id> [--apply]` (`run-undo.mjs`) reverses a run from `.exo/run/<id>/ops.jsonl`, which `run-child.mjs` and `land-run.mjs` append through `run-ops.mjs`: ref moves, worktrees and pushes. It never deletes work: a moved ref is backed up under `refs/exo/undo/<id>/`, worktrees and pushes are only reported, and it is a dry run unless `--apply` is given.

## Plan loop in this repository

- Plans here use `Land: local` and `Commit: <type(scope): subject>`. After `gate` passes, the lead squashes the run branch onto `main` as that commit.
- `exo:build <brief>` lands each task at depth 1: the main session sends every `Prompt:` of the window to `exo:build-task` in one foreground message and routes each return through `land-task.mjs`, `land-slot.mjs` and `next-task.mjs`. To resume, run it again, and it reads landed tasks from `Plan-task:` commits.
- A plan task lands only through that loop, so the lead and subagents commit no plan task on the run branch.
- Check a plan with `node skills/spec/scripts/plan-check.mjs --loop --run --plan <plan> --root <run worktree>`. With `--loop` it also runs the Success criterion command in the root and flags an exit 127 as a failure and a timeout (`EXO_CRITERION_TIMEOUT_MS`, default 120000) as a `[WARN]` line.
- A `plan-check*.mjs` fix adds a plan shape under `tests/fixtures/plans/ok/` or `bad/`, headed `<!-- expect: ok -->`, `<!-- expect: <first refusal line> -->` or `<!-- expect: [WARN] <line> -->` (exit 0, line printed) with optional `<!-- repo: <paths> -->` and `<!-- flags: <flags> -->` lines, and `tests/plan-check-corpus.test.mjs` runs each.
- A blocked task writes its partial work to `.exo/carry/task<n>-partial.patch` and the run tree is reset, so the partial work is not a commit. The lead then fixes the plan, or the cause in a worktree subagent, and reruns `exo:build`.
- A Gate or Success criterion repair on the run branch is a `fix(<scope>):` commit with no `Plan-task:` trailer. Otherwise the gate flags its files `UNPLANNED <file>`.
- The gate is one fresh subagent briefed with the skill and its inputs only. Its first brief line is `exo-kind: review`, and it runs no checks beyond the skill's.
- An `exo:build` run starts from one plain request in the current session, with no `exo:spec` or `exo:build`. It runs in its own worktree on `improve/<tag>`, the lead dispatches the worker subagents and runs `round.mjs`, and at Stop the lead squashes the kept commits and writes the `CHANGELOG.md` line.
- Non-run subagent work lands in one integration worktree under `.claude/worktrees/`. Merge the subagent branches, fetch, and rebase onto `origin/main`, and after the rebase every line of the change stays under `## Unreleased`. `worktreePath(name, from)` in `lib/checkout.mjs` (the directory is required, and `verify/checks/worktree-paths.mjs` fails a call without it) is the one place that builds a worktree path: `<main checkout>/.claude/worktrees/<name>`, so a run slot is `.claude/worktrees/<run>-task-<n>`.
- `createWorktree` in `lib/checkout.mjs` always copies the main checkout's gitignored `.env*` files into a new worktree, with no setting and no question; only a red-green tree passes `env: false` and gets none, and a tracked `.env` file is left to the commit refusal.
- Cleanup drops a stash made on a run branch once its content is on `main`, and every other stash stays untouched.
- Every plan ends with a task that writes its `## Unreleased` line, so the line lands in the run's squash commit.
- Phases hand over through the brief and `.exo/` files.

## Run contract

- `lib/run-outcomes.mjs` is the one outcome table of the in-session build and gate: each row has a kind, an action (`continue`, `repair`, `amend`, `park` or `stop`) and the printed line. Only `stop` rows end the turn; `park` writes one file to `.exo/questions/`, which `gate-step.mjs` does for each question finding.
- Every repair, retry and round bound is a kind in `lib/loop-kinds.json`; see Loop budget.
- At land, `outside Files` is an `amend` when the path is in no other open task's `Files:`, is not protected and the task's Proof passes; the amendment prints as an `AMEND Task <n> <path>` line on `land-task.mjs` stdout and edits the plan's `Files:`.
- No hook refuses an edit outside a task's `Files:`; `land-task.mjs` warns at landing for a path outside `Files:` and throws `OutsideFilesError` for a security-boundary path.
- `runCheck` in `lib/run-check.mjs` runs a check command through the tree-keyed record in `lib/check-cache.mjs`, with `env` and `fresh` options; the baseline, round, land-proof and run-tail checks go through it, and `changelog-task.mjs` runs its command directly. A skipped, empty or flaky-retried run records no pass.
- A re-entered gate skips steps recorded as passed on the same tree, in the headless journal shape.
- The gate review loop records the round-1 full and overlap reviews with their reviewed sha and does not repeat them on re-entry. Each later round lands one fixer commit per cluster and reviews only `<reviewed sha>..HEAD`. A script keeps the commit when its proof and the scripted checks pass and the fix-diff review raises no new `fix`. Otherwise it runs `git revert` and the finding becomes `report`. Each round appends one row to the run ledger, see Loop budget.
- `verify/checks/run-contract.mjs` fails `npm run check` on a stop or decide line outside the table, turn-ending prose outside it, or a check command outside `runCheck`.

## Loop budget

- `lib/loop-kinds.json` is the one table of loop kinds (`review`, `fix`, `look`, `proof`, `attempt`, `review-fix`, `wait`, `provider`, `refusal`). Each kind holds a round cap, the count it compares for progress and its owner script, and run.json `defaults` or an `EXO_*_MS` variable overrides a value. No script keeps its own retry, round or attempt cap.
- `lib/loop-budget.mjs` keeps one ledger file per plan run in the run folder. Every round of every kind appends one row (kind, round, open before, open after, wall ms, cost when known, verdict `keep`, `discard` or `stop`), and gate start, resume and re-entry read it and do not reset it.
- The script prints one line `LOOP <kind> CONTINUE|STOP <reason>` before each round. The cap is 3 by default (one full pass and at most two fix rounds), and `fix`, `review-fix` and `refusal` are 2. A round whose open count is not lower is reverted and its kind stops. One run-wide wall budget and `maxRunUsd` (where cost is known) are checked before every kind. At STOP the last green commit stays, open items go to the run report as `report` and the loop ends with no question.
- Only a finding with a verifiable criterion or a look fail line starts a fix round. A concern, note or question goes to the report. A fix diff that touches the judge (probes, tests named in Proof, `look.mjs` assertions, review prompts) is discarded, and `fix-diff-scope.mjs` handles `+++ /dev/null`.
- Every refusing gate returns all violations in one refusal and repairs what is deterministic; each refusal of one dispatch is a `refusal` round, and after the cap the gate stops with one line naming every rule.
- Every loop ends in one of two states named by `END_STATES` in `lib/loop-budget.mjs`: `rounds-spent` or `no-progress`; `decide` returns either as `state`, and `lib/run-outcomes.mjs` holds the follow-up row of each.
- `node lib/loop-budget.mjs --report <run dir>` prints rounds, wall and cost per kind, and the run report includes it.
- A check fails a numeric retry, round or attempt cap literal outside the table in `skills/`, `lib/`, `hooks/` and `agents/` scripts, a loaded-prose rerun instruction that names no kind, a kind with no consumer script or test, and a refusing rule module that returns on its first violation.

## Hooks

Other variables, each read through `environmentMs` unless noted: `EXO_BUILD_STALE_MS` (`lib/build-progress.mjs`, 3600000) is the age at which build progress counts as stale; `EXO_RUN_REPAIR` (`hooks/run-no-wait.mjs`, any value) makes the no-wait guard ignore the run task; `EXO_TEST_POOL_TIMEOUT_MS` (`lib/test-pool.mjs`, plain number) bounds one test file; `EXO_RED_BASE_MARGIN_MS` (`lib/red-green.mjs`, 60000) is the margin added to the base run time of a red proof; `EXO_RESEARCH_FANOUT_MS` (`lib/research-route.mjs`, 30000) is the research age after which fan-out routing stops; `EXO_STALL_MS` (`lib/stall-guard.mjs`, 60000) is the stall guard threshold.

Rules for writing a hook live in `skills/edit-skills/references/hook-shape.md`.

`hooks/hooks.json` registers one hook process per event and matcher rather than one per feature: `hooks/session-start.mjs` on `SessionStart`, `hooks/session-end.mjs` on `SessionEnd`, `hooks/dispatch-bash.mjs` on `PreToolUse` for `Bash`, `hooks/agent-effort.mjs` for `Agent` and `hooks/dispatch-edit.mjs` for `Edit`, `Write` and `MultiEdit`, and `hooks/context-limit.mjs` for the other matched tools (`Read`, `Glob`, `Grep`, the web tools, `Skill`, `NotebookEdit`, `ToolSearch`, `mcp__.*`). The context note at 112.5k and the refusal at 150k each name exo as their source and the result-file route (write the file the brief names; Write still works past the hard limit), and no `SubagentStart` hook exists; `verify/budgets.mjs` locks the `SubagentStart` text of `hooks/hooks.json` at 0 bytes. `hooks/run-no-wait.mjs` runs on `PreToolUse` for `AskUserQuestion` and on `Stop`, and acts only inside an exo run (`EXO_RUN_DIR` set): it denies a question and blocks an end without a status line, telling the session to decide from the spec and settings and log the choice in `<EXO_RUN_DIR>/decisions.md`. Blocks are counted per session in `blocks.json`; after 2 the end passes and `<EXO_RUN_DIR>/blocked` holds `Task <n>: BLOCKED <last line>`. The Bash dispatcher fixes two shell gaps through `lib/shell-fixes.mjs` by adding a prefix and leaving the command text as written: under zsh a command gets the bash behaviour it needs from the `ZSH_OPTIONS` table: `setopt noequals` for an `=` word, `shwordsplit` for a `$name`, `${name}`, `$1` or `$@` outside quotes and `ksharrays` for a `${name[i]}` subscript (the unmatched-glob error is cut session-wide by the `nonomatch` line the SessionStart hook adds to `CLAUDE_ENV_FILE`), and a command naming `timeout` gets a `timeout()` shell function wrapping a perl alarm only when no `timeout` is on PATH, so the shell resolves every `timeout` itself; a command calling `sed` with a bare `-i` on BSD sed gets a `sed()` function that passes `-i ''` to `command sed`. It skips this in a run session (`EXO_RUN_SESSION=1`, set by `childEnv` in every run-plan child), whose prefix allow rules a prefixed command would no longer match; where run-plan installs the stall guard, `hooks/run-stall-guard.mjs` applies the same fix. Every agent starts a long command in the background, ends its turn and writes its final result after its own shells have ended; no `SubagentStop` hook exists, and `lib/live-shells.mjs` refuses once a result-file Write while an own shell runs. The Bash dispatcher also denies, only when the call carries an `agent_id`, a `git` command matching `SHARED_STATE_GIT` in `lib/git-deny.mjs` (stash, worktree remove, prune and move, branch delete and rename), the list `run-session-rules.mjs` builds its `DENY_RULES` entries from. The list stops a subagent's accidental direct git call on shared state and is not a sandbox: git code fed to a shell interpreter through stdin, a here-string or a pipe (`bash <<< "git stash"`, `echo "git stash" | sh`) is out of scope. It runs the context check, in process, and `agent-effort.mjs` runs it too, so those tools get no extra process. The context check acts only in subagents and detached run sessions; the interactive main session gets no note and no refusal from it. The session text carries one `- Off-brief return →` line: an agent that loops, does unrequested work, weakens a test or returns the wrong shape gets one SendMessage naming the drift and the rule it broke, and is stopped or redispatched only when its next return still drifts or it is past its hard context limit; a new review finding keeps the `**Fix rounds.**` rule. Hook code (`hooks/**/*.mjs` plus `lib/hook-input.mjs`) stays within `HOOK_LINES_LOCK` in `verify/budgets.mjs`, checked by `verify/checks/hook-budgets.mjs`. Each script registered in `hooks/hooks.json` stays within its row of `HOOK_WORK_LOCK`: the modules it loads and the files it reads on a fixed input, counted by `verify/hook-work-preload.mjs` through `module.registerHooks` and wrapped `fs` readers, checked by `verify/checks/hook-budgets.mjs`. A registered script with no row fails the check.

- **SessionStart** (startup, resume, clear, compaction): writes the plugin-root pointer to `~/.claude/exo/plugin-root` (under `CLAUDE_CONFIG_DIR` when set) only when `CLAUDE_PLUGIN_ROOT` resolves to the copy the hook runs from, so a hand run or a cloned copy leaves it alone. Beside it, `plugin-main` names that copy's main checkout, read from its `.git` file; the status line launcher, the `exo` shim and `exo-cli.mjs` use it once the pointed worktree is gone. On Claude Code the hook also upgrades an old status line launcher in place. It injects only this context, the text of `hooks/session-routing.md` and `hooks/session-rules.md` first so it is a prefix shared across sessions and the rest after it: the handoff and memory pointers when those files exist, the handoff pointer quoting the prompt of its last `Resume:` line, on compaction, clear or resume a pointer to the newest `.exo/*/progress.md` modified within `EXO_PROGRESS_POINTER_MS` (default 1 hour), the settings line (no reply-length entry or rule text. Short replies come from the `exo:adhd` output style), the Codex host note on Codex, and the routing and session rules from `hooks/session-routing.md` and `hooks/session-rules.md` when those files exist, in that order, then on Codex the dispatch rules from `hooks/dispatch-rules.md`. On Claude Code it clears the session's dispatch marker instead. The welcome and the book sentence are not injected.
- **SessionEnd** (`hooks/session-end.mjs`, skipped in a sidecall and inside an exo run): writes a mechanical handoff stub at the `save-session` handoff path only when no handoff was written during the session; the stub holds HEAD, branch, the `## Goal` section of the newest progress file (omitted text falls back to a not-recorded line), up to 50 uncommitted files, the newest `.exo/*/progress.md` and a `Resume:` line, and carries `Source: auto`. A handoff the model wrote in the session, or an earlier one without that mark, is kept.
- **Refusal memory**: `lib/refusal-memory.mjs` counts a refused call per session; hit 1 gives the guard text, and hit 2 a reminder naming the route, and hit 3 on the stop text `record the gap`, which is the gap instruction, so no gap is stored. Every hook sends its refusals through `lib/hook-refusal.mjs`, which takes the route from a `Do instead:` clause. The rules in `FIXED_RULES` keep one fixed text.
- **Guard kinds**: `guardKind(id)` in `lib/guard-rules.mjs` is the one table of which rules warn; `refuse(id, reason)` in `lib/lazy-steps.mjs` returns `warn(reason)`, a context line that lets the call run, for a warn rule and `deny(reason)` for every other. The `code-rules` step of `hooks/dispatch-edit.mjs` and the context-target, result-line and intake-glob rows in `lib/context-decisions.mjs` warn the same way. The `commit-evidence` step warns with a `[WARN]` line, and `land-task.mjs` prints a code-rule finding as one `[WARN]` block and lands. Delete, spend, network and security guards stay hard, and so does `commit-attribution`.
- **Delegation triggers** (`hooks/session-rules.md`): the session text keeps the main session inline by default and lets work leave it only when a trigger it can check before starting holds: T1 small task (inline), T2 web research or a long search whose output the lead need not keep (`exo:orchestrator`, which dispatches the `exo:research-worker` agents), T3 2+ independent parts of 6+ tool turns each (one subagent per part, Agent calls in one message), T4 steps that each need the previous result (one worker, unsplit).
- **Prune** (`lib/exo-prune.mjs`, called from `hooks/session-start.mjs`, skipped under `TE_SIDECALL=1`): at most once per 24 hours per project, gated by the mtime of `.exo/pruned-at`, the hook deletes each top-level `.exo/` entry, and each child of the containers `kept/`, `run-plan/` and `logs/`, whose newest file is older than `defaults.pruneAfterDays` (7 in `lib/run-providers.json`, overridable in `~/.config/exo/run.json`). It leaves `.exo/run/`, symlinks, the folder holding the newest `.exo/*/progress.md` and the stamp unpruned, and an error leaves the files in place. Build and task logs go to `.exo/logs/<name>.log`.
- **Dispatch sizing** (`lib/worker-size.mjs`, called from `hooks/agent-effort.mjs`): estimates a brief's read cost as the bytes of its `Reads:` paths divided by `defaults.bytesPerToken` (2 in `lib/run-providers.json`) plus `defaults.fetchTokens` (1600 in `lib/run-providers.json`) tokens per fetch unit, `Fetches: <n>` times the `search.mjs` default `--limit` (5), so one fetch costs 8000 tokens (one fetch is one `search.mjs` call on the reddit route, where `n` is the thread count asked for divided by the call's `--limit`, rounded up, and one page otherwise, and a raise sent by the dispatching orchestrator is valid), against a read budget of `defaults.agentContextTarget / 2`. It checks an `exo:orchestrator` worker dispatch whose brief lacks `Reads:` or `Result:` or exceeds the budget, and a `general-purpose` or `claude` dispatch from any other caller whose brief has neither `Reads:` nor `Fetches:` or exceeds the budget. Only an over-budget brief is refused, naming the estimate and asking for a split into more agents. A missing or invalid `Reads:`, `Result:` or `Fetches:` line, an unresolved path, a `Reads` label and a `head -c` page cut pass with one warning line.
- **Script-size step** (`SCRIPT_SIZE_STEP` in `hooks/dispatch-bash.mjs`): for a call carrying an `agent_id`, saves a Bash command over 4 KB under `.exo/` and rewrites it to `bash <saved path>`, and warns, letting the call run, when the save fails.
- **Workers check** (`hooks/agent-effort.mjs`): an `exo:orchestrator` call with no `Workers: <n>` line, or an n below 1 runs with a warning in the call's context; an n over `defaults.orchestratorWorkers` (4) is refused with a reason that tells the lead to plan phases and slices for a larger job.
- **Lead Reads check** (`hooks/agent-effort.mjs`): an unnamed worker the lead dispatches with no `Reads:` line runs with a warning that gives the line to add, and one with a `Result:` line is refused, because the result file is the orchestrator's handoff.
- **Dispatch role check** (`roleFields` in `lib/context-decisions.mjs`, called from `hooks/agent-effort.mjs`): maps the caller to a row of `harnesses/coordination-contract.json` (no `agent_id` is main, `orchestrator` is subagent-coordinator, an unknown type is fork-coordinator, any other type is worker) and refuses an `Agent` call when that row has `mayDispatch` false.
- **Slice file** (`lib/slice-state.mjs`): each allowed orchestrator dispatch appends one byte to `exo-slice-<agent id>` in the temp folder, and call n+1, n being the brief's `Workers:`, is refused before it runs.
- **Pre-dispatch step** (`predispatchDecision` in `lib/slice-state.mjs`, called from `PREDISPATCH_STEP` in `hooks/dispatch-bash.mjs` and from `hooks/context-limit.mjs`): until an orchestrator's first dispatch, adds a note to a Read outside its brief's `Reads:` paths and to any Read or Bash call past `defaults.orchestratorPredispatchReads` (4), pointing the reading to workers.
- **Reddit step** (`REDDIT_STEP` in `hooks/dispatch-bash.mjs`): `search.mjs` is the only Reddit route. A Bash curl or node fetch to reddit.com is refused here with a Do-instead naming `search.mjs`, and a WebFetch to reddit.com is refused by `redditRouteDecision` in `hooks/context-limit.mjs` and pointed to the live `search.mjs --url` thread read. Every request is an in-page `fetch` in a headed Brave or Google Chrome that exo starts with its own profile at `(XDG_CACHE_HOME or ~/.cache)/exo/reddit-browser`, reused through `DevToolsActivePort`. Search uses `/svc/shreddit/search/`, and a thread read uses `/comments/<id>.json` plus one call per `more` stub, capped by one run.json `defaults` value; `signals` state `read <n> of <num_comments> comments`. Not logged in, no supported browser or a 403 prints one `status: blocked reddit <reason>` line naming the fix and exits 1 with no retry. `search.mjs --source reddit --login` opens the browser on the Reddit login page, and the password is typed only there. A WebSearch without `site:reddit.com` is the only other way to name a thread.
- **Sleep step** (`SLEEP_STEP` in `hooks/dispatch-bash.mjs`): adds a note to a foreground Bash command with `sleep` in command position and to a foreground `until` or `while` loop that sleeps; background calls and Monitor pass. The sleep, watch and stash text guards skip a heredoc body fed to `cat`, `tee`, `python`, `python3` or `node`, and still scan one fed to `bash`, `sh`, `zsh` or `eval`.
- **Read cap** (`readCapDecision` in `lib/context-decisions.mjs`, called from `hooks/context-limit.mjs`): runs an agent's Read that would return more than the room left of its context target (`agentContextTarget` minus the transcript tokens, in bytes) with the offset and limit that fit and says where to continue, and warns only for a first line over the room; there is no fixed byte cap, and past the target the harness output limit applies. The lead is skipped. A cut runs in every permission mode: `contextFields` returns `updatedInput` with no `permissionDecision`, so Claude Code applies the rewrite and the user's prompt or allow rules still decide the call (probed with `claude -p` in default and plan modes). Only the Bash cap keeps `CAPPED_MODES`, because a rewritten command no longer matches a prefix allow rule.
- **Search cap** (`searchCapDecision` in `lib/context-decisions.mjs`, called from `hooks/context-limit.mjs`): under the same bound and mode rule, a Grep gets the `head_limit` that fits (bound over `defaults.searchLineBytes`, 200) and a ToolSearch the `max_results` that fits (over `defaults.toolSchemaBytes`, 2048). In other modes either is denied with that number. A `select:` ToolSearch is skipped. Glob (at most 100 paths) and WebSearch (`fetchTokens`) have no size field, so either is denied only when its largest output passes the room left; a Glob is steered to Grep with `glob` and `head_limit`.
- **Result cap step** (`RESULT_CAP_STEP` in `hooks/dispatch-bash.mjs`): in a `bypassPermissions` or `auto` session, rewrites a capped agent's foreground Bash command to cut its output at the same byte cap with the full log in `exo-bash/` under the OS temp folder, naming the log path only on the cut line; `run_in_background` calls are left alone. `hooks/session-start.mjs` deletes those logs once they are older than `EXO_SAVED_OUTPUT_MS` (one day).
- **Bash cap step** (`BASH_CAP_STEP` in `hooks/dispatch-bash.mjs`, `lib/bash-cap.mjs`): in a `bypassPermissions` or `auto` session outside a run session, wraps a subagent's foreground Bash command in `timeout N "${SHELL:-/bin/sh}" -c '...'`, with N the call's `timeout` (default `BASH_DEFAULT_TIMEOUT_MS`, clamped to `BASH_MAX_TIMEOUT_MS`) minus `EXO_BASH_CAP_MARGIN_MS` (default 5000, at most half the limit) in whole seconds, so it exits 124 before Claude Code moves it to the background. Inside the result-cap wrapper the timeout sits within the subshell, so the head and log path still print. It applies on top of a script-size rewrite, defines the `timeout` function where no binary exists, and skips `run_in_background` calls, the lead and a command that starts with `timeout`.
- **Cap defaults** (`lib/run-providers.json` `defaults`): `orchestratorWorkers` (4), `orchestratorPredispatchReads` (4) and `scriptBytes` (4096), each overridable in `~/.config/exo/run.json`.
- **Context-limit gate** (`hooks/hooks.json`): the Read, Glob, Grep, web, Skill, ToolSearch and MCP entry starts Node only for Read, Skill, a run session (`EXO_RUN_HANDOFF`) or an agent whose `exo-context-<agent id>` marker shows it past its soft limit.
- **Hook cost check** (`verify/checks/hook-budgets.mjs`): fails when `hooks/hooks.json` has more entries than `HOOK_ENTRIES_LOCK`, or the session, dispatch and Bash deny text has more bytes than `HOOK_TEXT_BYTES_LOCK`.
- **Sizing defaults** (`lib/run-providers.json` `defaults`): `agentContextTarget` (60000 tokens), `bytesPerToken` (2), `fetchTokens` (1600), `imageTokenCap` (1600), `pdfPageTokens` (3000) and `binaryReadTokens` (500), each overridable in `~/.config/exo/run.json`; `verify/budgets.mjs` and plan-check keep their ratio of 4.
- **Dispatch rules** (`hooks/dispatch-rules.mjs`): the first `Agent` call of a main session, outside a detached run session, gets the text of `hooks/dispatch-rules.md` (the lead passes no `model` or `effort` for `exo:` agents, long command output goes to a log, and an unnamed delegate's brief opens with `exo-kind: hardest` when it leaves a design, architecture or solution choice open or asks for an unknown cause, `exo-kind: build` for a fully decided fix, a `Reads:` or `Fetches:` line in an unnamed worker brief, a `Workers: <n>` line of at most 4 on each `exo:orchestrator` slice of a larger job, and ending the turn to wait for the notification after a dispatch) as `additionalContext` from `hooks/agent-effort.mjs`; a marker file `exo-dispatch-<session id>` in the temp folder keeps later calls free of it until the next SessionStart clears the marker. A subagent's call gets none, as it got no session text.
- **Unnamed job words** (`filled` in `hooks/agent-effort.mjs`): an unnamed `Agent` call with no `exo-kind:` line takes its kind from `unnamed.jobs`; a description word counts when it is a job word or the job word plus `s`, `es`, `d`, `ed` or `ing` (a silent final `e` dropped before `ing`), case-insensitive, so `pickup`, `picker`, `designated`, `findings` and `fixtures` match nothing, and the first job word in table order wins over all description words, so design words outrank build words, and `Fix edit-evidence false block cause` runs on `hardest` and `Fix the typo` on `build`. No match and no label line runs the call as `build`, as the next bullet says. `readKindTable` rejects a job word naming an unknown kind.
- **Unlabelled dispatch default** (`defaulted` in `hooks/agent-effort.mjs`): under budget `on`, a `general-purpose` or `claude` `Agent` call with no model, no effort, no `exo-kind:` line and no job word in its description runs as `build`, and the hook prepends `exo-kind: build` to the prompt through `updatedInput`. A call whose first line names an unknown kind, with no job word, is denied; the reason tells the lead to use `hardest`, `build` or `review`. A labelled call, a call with a job word, an `exo:` agent and any call under `off` pass.
- **Edit-impact note** (`lib/edit-impact.mjs`, a step in `hooks/dispatch-edit.mjs`): the first `Edit`, `Write` or `MultiEdit` of an existing non-test source file per session adds one note naming at most 6 files that import it (at most 3 of them tests), found by one `git grep --no-index` on the file's import name. Seen files are remembered in `exo-impact-<session_id>` under the temp dir. The search stops after `EXO_EDIT_IMPACT_MS` (default 2000); a timeout, an empty result or a missing `session_id` adds nothing.
- **Context limits** (`lib/context-limits.mjs`, with `hookAgentType` and `contextDecision` in `lib/context-decisions.mjs`, where `hookAgentType` is the caller's agent type from the hook input's `agent_type`, else from the subagent meta file): each matched tool call reads the context size from the tail of the caller's own transcript. The hard limit is `contextLimit()`: `defaults.contextLimit` from `~/.config/exo/run.json`, else from `lib/run-providers.json`, a positive integer in tokens; the soft limit is 75% of it, `SOFT_RATIO`. Claude Code gives a hook no window size, and a transcript's model id carries no `[1m]` mark, so the limit is a quality cap, not a window guess. Only the status line shows a window: the auto-compact window Claude Code compacts at, from `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (`200000`, `200k` or `1M`, held to 100k-1M), else the first of project local, shared project (both under `workspace.project_dir`) and user settings that sets `modelSettings.<model>.autoCompactWindow` (`auto` keeps the default) or `autoCompactWindow`. It is capped at `context_window.context_window_size`, and with none set it is that size. `run-plan.mjs` and the status line's missing-size fallback read the same function. It acts on subagents and detached run sessions only, and the interactive main session gets no note and no refusal at any size. A subagent is warned once, remembered in `exo-context-<agent_id>` under the temp dir. Past the soft limit it adds a note to finish the step and hand off. Past the hard limit it denies the tool, and the session ends with its report or handoff.
- **Cap headroom** (`warnNearCap` in `skills/spec/scripts/plan-check-size.mjs`): in a root holding `verify/budgets.mjs`, plan-check adds `[WARN] Task N edits <file>` for each unlanded task whose `Files:` lists a skill or agent with fewer than `defaults.capHeadroomTokens` (50, `lib/run-providers.json`, override in `~/.config/exo/run.json`) tokens of body headroom left, unless that task or an earlier one lists a `references/` file of the same skill. It measures with the root's own `verify/body-size.mjs`, run in a child process that `EXO_BODY_SIZE_TIMEOUT_MS` (default 60000) stops; a timeout skips the check with a warning. A warning does not fail the check.
- **Proof command on PATH** (`checkProofTestsListed` in the same file): plan-check fails `Task N: Proof starts with <command>, which is not on this host's PATH` when the first word of `Proof:` is a plain command name that no `PATH` directory holds.
- **Provider models** (`providers.deepseek` and `providers.zai`, `lib/run-providers.json`): `deepseek` maps every tier, `ANTHROPIC_MODEL` and the subagent to `deepseek-flash`, with efforts `low`, `high`, `max` and no provider `effort`; `zai` maps Haiku to `glm-5.3-flash` and the rest to `glm-5.3`. `resolveProvider` adds `EXO_PROVIDER=<name>` to the session env. With no provider `effort` in the entry, each dispatch follows its `deepseek` kind column and only an explicit `--effort` sets `CLAUDE_CODE_EFFORT_LEVEL`, because that variable outranks a dispatch's effort. Each provider's column in `lib/model-kinds.json` picks a subagent's effort: `hooks/agent-effort.mjs` takes the session's `EXO_PROVIDER` column when the table lists it, else the `claude` column. The tier, effort and `kindEfforts` values of each provider live in `providers` of `lib/model-kinds.json`. `budgetPin` in `run-plan.mjs` pins an `exo run` task session to a listed provider's `effort` with no model. Neither block sets a `[1m]` suffix or `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, so Claude Code compacts at its default window. Widen it per provider in `env` in `~/.config/exo/run.json`.
- **Provider keys and sessions** (`skills/build/scripts/exo-cli.mjs`): `exo key set <provider>` stores the provider's key in `~/.config/exo/keys.env` through `writeKey` in `run-keys.mjs`; it reads the key without echo on a terminal or one line from stdin when piped, keeps it out of output, and refuses a provider with no `key` in the run config. `exo claude [--provider <name>] [--effort <level>] [-- <claude args>]` (`exo-claude.mjs`) starts an interactive Claude Code session with the provider's environment from `resolveProvider`, drops an inherited `ANTHROPIC_API_KEY` for a non-`claude` provider, refuses a missing key with the line `exo key set <name>`, and refuses inside a Claude Code session.
- **Delegate limits**: each agent that builds, reviews or repairs sets `maxTurns` in its frontmatter (60, including `orchestrator`). The harness ends a delegate at that turn.

Each hook entry pins `"shell": "bash"`, else a Windows host without Git Bash falls back to PowerShell; the hook command stays in shell form, not `args`, so Claude Code resolves the shell, not `bash` on `PATH`. The session hook stays Node (`hooks/session-start.mjs`), with no `jq`. `.gitattributes` forces LF, because a CRLF shebang fails silently on Windows.

The plugin ships no permission guard: a cap on what a machine may do belongs in that machine's own configuration.

The `Skill` path of `hooks/context-limit.mjs` maps each lead `exo:` skill call to a topic with `lib/topic-switch.mjs` (spec, build, gate, ship and find-cause share one), keeps the session topic in a temp file and adds a context line suggesting a fresh session when the two differ; it adds no hook entry and makes no model call.

- **Figure sources** (`unsourcedFigures` in `lib/evidence-rules.mjs`): returns each report line holding a cost, count or wall figure with no path or command beside it; the orchestrator sends such a report back.

## Codex

`lib/model-kinds.json` stays the one table: `provider` stays `claude`, and its `providers.codex` block maps each tier to a Codex model and effort. `harnesses/codex/generate.mjs` applies `harnesses/codex/rules.mjs` to the Claude sources and builds the Codex tree in memory: each skill rewritten with its `agents/openai.yaml`, and `agents/exo-<agent>.toml` per agent, which names no `sandbox_mode` so the agent inherits the session sandbox. The Codex installer builds it fresh on every install, so the tree stays uncommitted; `npm run generate` writes it to the gitignored `harnesses/codex/generated/` for inspection only, and nothing reads that copy. `npm run check` fails when the sources cannot generate the tree.

`harnesses/codex/overrides/<path under generated>` replaces one generated file and opens with `<!-- exo:override source-sha256=<hash> -->`. Add one only after a skill reads wrong in a real Codex run; a changed source hash fails `npm run check`.

`install.mjs` runs one adapter per harness, listed in `harnesses/registry.mjs`. An adapter is `harnesses/<name>/adapter.mjs` exporting `name`, `label`, `detect(env)`, `install(plan)`, `update(record)`, `remove(record)` and `recorded(env)`; a new harness is one adapter folder plus one registry line. The Claude adapter runs `claude plugin install exo@blauwtje -s <scope>`; the Codex adapter copies the generated skills and agents and merges the allowlisted hook entries from `harnesses/codex/hooks.mjs`. Each records its installs in `installed.json` under its config home.

Codex hooks and generated script commands run through `harnesses/codex/hook-entry.mjs` and `harnesses/codex/run.mjs`, which set `EXO_HOST=codex`; `lib/host.mjs` treats a missing or unknown value as Claude Code. Try an install against a scratch folder with `HOME=<dir> CODEX_HOME=<dir>/.codex node install.mjs --harness codex --yes`.

## OpenCode

`harnesses/opencode/generate.mjs` reuses the Codex rewrite helpers and file listing (`listFiles`, `posix`) and builds the OpenCode skills and `exo-<agent>` subagent files in memory; agent files name no `model`, and effort maps to a `#variant` only when `opencode.model` and `opencode.variants` are set in `~/.config/exo/run.json`. Codex and OpenCode agents share the preamble in `harnesses/codex/agent-preamble.md`; each host passes its own tool line. `harnesses/capabilities.json` holds each harness's hooks and efforts, and a static check fails when an adapter, its hook events or its effort column disagree with it. OpenAI models run through the OpenCode harness with the user's own provider key.

## Releasing

A release is cut weekly, not per merge: a scheduled run every Monday 06:00 UTC cuts it when `## Unreleased` holds an entry, and `gh workflow run release.yml` (or the Run workflow button on the Actions page, optionally with `-f level=patch|minor|major`) cuts one sooner. A scheduled run uses level `auto`, which reads the level off `## Unreleased`. `.github/workflows/release.yml` runs only on `main`. It checks with `npm run release-pending` whether `## Unreleased` holds an entry; if so it runs `npm run check` and `npm run bump`, commits `chore(release): <version>`, tags `v<version>`, pushes both and publishes the GitHub Release from `npm run release-notes`. With nothing under `## Unreleased` it cuts no release.

A change lands on `main` as one squashed commit carrying its changelog entry, and `### Highlights` when deserved, but no version. A change the user should read first gets at most three bold lead sentences under `### Highlights` in `## Unreleased`, in the commit that records it and not in a release commit; entries collect under `## Unreleased` until the next release. The release push uses `GITHUB_TOKEN`, which starts no further workflow, so the release commit does not release itself. After a release, `claude plugin marketplace update blauwtje` and `claude plugin update exo@blauwtje` install it locally; the marketplace compares only the manifest version, so an unbumped release installs as a no-op.

- **Caller output** (`lib/script-output.mjs`, imported as `#script-output`): a runner-facing build script prints only what the caller's next step reads and writes the full text to `.exo/logs/<name>.log`, named by one `Detail:` line; a passing Proof prints `Proof: <cmd>: pass (exit 0, <outcome>)`. The `script output` check fails a script named in `skills/build/SKILL.md` or `skills/build/references/rolling-window.md` that does not import `#script-output`, unless the exempt list in `verify/budgets.mjs` names it.

- **Changed-test trial** (`trialActive` in `lib/suite-command.mjs`): after `changedTestsTrialRuns` (run.json `defaults`, 10, enough clean runs to rule out a rare miss yet few enough to pay off within a plan) consecutive full runs of a whole-suite proof with no miss in `suite-shadow.jsonl`, the proof runs only the test files changed since the last full green and logs `full: skipped`. A miss restarts the count, and every `changedTestsTrialRuns`th run is a full one, so misses stay visible.
- **Proof and Data warnings** (`warnProofAndData` in `skills/spec/scripts/plan-check-files.mjs`): plan-check adds `[WARN] Task N: Proof starts with <path>` when the first word of `Proof:` is a path absent from the root and from `Files:`, and `[WARN] Task N: Data: names <path>` for a backticked `Data:` path that `Files:` omits. A warning does not fail the check.
