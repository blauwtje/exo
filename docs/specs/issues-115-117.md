# Wave worktrees wait for their build, and boundary words gate the land

## Goal
A wave worktree leaves only after its build returned and never through `--force` (#115), the land gate fails when an edited skill, agent, rule or hook prose file loses a boundary word nobody named (#117), and a test-covered output-only script change under `skills/` or `hooks/` keeps `none (output only, test covered)` (open review note from the short-reports-text-review run).

## Decisions
- #115 in-flight guard: `skills/build/scripts/remove-worktree.mjs` gets `--report <file>` and refuses, removing nothing, while that file is absent; `skills/build/references/wave-worktrees.md` step 4 passes `--report "<root>-task-<n>/.exo/implementer-<n>.md"` for every wave folder. The build writes that report last, and each wave folder is new, so a present report means the build returned. Alternative: a prose-only rule in wave-worktrees.md; rejected, the `design-ui-fast-preview` run shows prose alone failed. Closed by: spec (user delegated every choice).
- #115 no `--force`: `remove-worktree.mjs` drops its `--force` flag and `force` option (`--force` becomes a usage error, exit 2) and gains `--patch <file>`: it refuses unless that file exists and is non-empty, then lets `git worktree remove --force` drop the dirty tree after the usual `.exo/` and `docs/specs/` copy checks. A clean folder needs neither flag. Alternative: keep `--force` and stop passing it; rejected, nothing would stop the next forced call. Alternative: leave every unlanded folder in place; rejected, wave-worktrees.md counts a left-behind worktree as a defect. Closed by: spec.
- #115 build gone without a report, or a stalled slot (six `wait-report.mjs` runs, no report): the folder stays, and the task's `BLOCKED` line names the folder and the refusal. No override flag. Rationale: the issue's rule that a refusal leaves the worktree; a build that may still write gets the benefit of the doubt. Closed by: spec.
- #115 block, refusal and cleanup: before step 4 removes any wave folder, the run waits for every still-running build of that wave with `wait-report.mjs --any` (at most six runs); wave-worktrees.md line 33's "no turn ends while `git worktree list` still prints a wave worktree" gains the exception of a folder `remove-worktree.mjs` refused, which the return names. `agents/run-unit.md` stays as is: it already routes every wave removal to wave-worktrees.md (`agents/run-unit.md:18`) and sits at 716 of 750 tokens. Closed by: spec.
- #117 scope: every `.md` file under the top-level `skills/`, `agents/`, `rules/` or `hooks/` folder that exists at both the base and the working tree; added and deleted files are skipped. Words: `only`, `not`, `no`, `never`, `every`, `each`, `all`, `full`, `except`, `unless`, counted as whole words, case-insensitive, over the whole file text. Closed by: spec.
- #117 base: `origin/main`, as `verify/checks/plugin-version.mjs:17` uses it; head is the working tree on disk, so uncommitted edits count. Missing `origin/main` or no git → `UNRUN`, never `FAIL`. Check label: `boundary words`. It runs under `--static` and in the full run. Closed by: spec.
- #117 named drops: a line `Drops: <word> in <path>[, <word> in <path>]` allows that word's count to fall in that file. Sources: every such line in `git log origin/main..HEAD --format=%B`, plus the environment variable `EXO_DROPS` with the same `<word> in <path>[, ...]` value. `land-task.mjs` sets `EXO_DROPS` from the task's `Drops:` field when it runs the land gate (the gate runs before the commit exists), and appends `Drops: <value>` after the trailers of a compact task's derived commit, so the later full check reads it from the log. Closed by: spec.
- #117 FAIL line: `boundary words: <path>: <word> <old> -> <new>` per drop, joined with `; `, ending with how to name a deliberate drop (`Drops: <word> in <path>` in the plan task's field line or the commit body). Closed by: spec.
- #117 self-test: `verify.mjs` gains `--boundary-base <dir>`, which reads base files from that directory instead of git; `verify/self-test.mjs` passes `--boundary-base <repository>` only to a scenario marked `boundaryBase: true`, so every other scenario (fixture without `.git`) sees `UNRUN` for this check and keeps its exact FAIL set (`judgeScenario`, `verify/self-test.mjs:357`). Closed by: spec.
- #117 docs: `skills/spec/references/task-list.md` is not edited; it sits at its 750-token ceiling. The `Drops:` syntax lives in the FAIL line and in `CONTRIBUTING.md`. `lib/plan-tasks.mjs` already keeps unknown `Key: value` segments and `plan-check.mjs` passes unknown keys, so a `Drops:` field needs no parser change. Closed by: spec.
- Review note `review-08cca17` (pick-reviewer order): an instruction path counts only when its extension is not in `SCRIPT_EXTENSIONS` (`lib/script-extensions.mjs:3`); a script under `skills/` or `hooks/` then follows the existing script lines, so a test-covered output-only diff gets `none (output only, test covered)`, and any other script change still gets the light pick. Alternative: keep the order and pin it with a test; rejected, a script is not instruction text and #118 targeted text. Closed by: spec.
